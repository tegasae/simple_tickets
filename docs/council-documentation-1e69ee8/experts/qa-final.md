# Итоговая проверка QA

Комплект `docs/council-documentation-1e69ee8/`. Фактический контракт сверён с опубликованным `1e69ee8`. Штатный прогон 35 из 35 и отдельная проверка 12 групп HTTP-сценариев воспроизводимы по [командам валидации](../meta/validation.md).

- Исправления каталога подтвердились. `GET/POST /admin/roles/admin` используют `AdminRoleApplicationService` и `role.assign`; `GET /admin/roles/user` использует `UserRoleApplicationService` и `role_user.assign`. Очистка плановой даты использует `clear_schedule` и `ticket.operation`, отзыв ролей сотрудников использует `revoke_role` с правом соответствующей области. Снятие отдела и учётной записи Admin тоже указывает только вызванные обработчики.
- Пользовательский Markdown содержит отдельные заголовки всех шести согласованных профилей, ситуации для каждого профиля и отдельный раздел сотрудников клиента. Обычный сотрудник соотнесён с базовой ролью, Ведущий инженер с учебным Опытным инженером. Менеджеру в рекомендованном профиле даны оба диспетчерских полномочия. Пожелание сотрудника клиента проверяет диспетчер. Отключение публичного поля рекомендации описано в backend как будущее решение C‑13. В пользовательской части нет API-маршрутов и примеров кода.
- Все шесть пользовательских SVG лежат по ссылкам и считываются как XML. Отрисованные схемы показывают происхождение пары, два жизненных цикла, работу горячей линии, регистрацию задним числом и отключение. В текущем Markdown обоих руководств все найденные относительные файловые ссылки разрешаются.
- Первый PDF пользователя визуально проверен целиком, с полноразмерной сверкой оглавления и двух насыщенных схем. Размер A4, 18 страниц, 26 закладок, 25 исходных заголовков находятся в тексте. 78 внутренних аннотаций разрешаются в именованные цели. Русские шрифты встроены с Unicode. Ошибок извлечения и контента за границей страницы нет. Последняя страница содержала только заключительный абзац; при переносе файла ссылка из PDF на backend указывала на абсолютный путь каталога сборки. Оба замечания переданы координатору для повторного рендера.

Обе схемы жизненного цикла показывают корректные подмножества. Остальные схемы сверены с созданием пары, условиями горячей линии, ретроспективой и каскадами отключения.
