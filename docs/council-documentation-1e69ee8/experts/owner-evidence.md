# Пакет решений и входов для консилиума

- Локальный источник: local/, HEAD d497e75d4937e8edea98783a5af924c247622e06, отпечаток 9b84001743d181d1cf4db69f4cd70d6a6aed673fba2899dbf6bbb5ea748eb58d. Включены локальные отчёты, части обзоров и обсуждения. Проверять локальное поведение отдельно.
- Опубликованный источник: published/, HEAD 1e69ee8a6368d8bd1bf9971e4a7501f879e2cf69, отпечаток 3faafeef2ebb36fb949cebce26f3e3f6f90407e2cca988f448ecd4de19df9ea6. Новее по коду. Координатор уточнил, какой снимок основной, до ответа исследовать совместимые положения и расхождения. Рабочая копия остаётся без изменений.
- C-01. Текущая постановка задачи, 28.11.2026. Шесть пользовательских названий заданы владельцем: Обычный сотрудник, Инженер, Инженер с правом работы на горячей линии, Ведущий инженер, Менеджер, Руководитель отдела. Название горячей линии временное, означает право брать рекомендованную для удалённой работы заявку, самоназначаться и начинать работу.
- C-02. Обсуждение #28. Самоназначение только для горячей линии. Рекомендацию даёт диспетчер с соответствующим правом. Для начала удалённой работы это право обязательно независимо от того, кем был назначен сотрудник. Обычный старт уже назначенным инженером возможен по обычному праву работы, отдельное право горячей линии для обычного старта не требуется. Проверить условия обоих снимков по коду.
- C-03. Обсуждение отключения. Владелец подтвердил закрытие READY_FOR_REVIEW при отключении владельца либо отдельно контактного User. Если работа по заявке отключённого клиента сохраняется в процессе и позже приходит на проверку, подтверждение действующим Admin допустимо. Сопоставить разные операции отключения Admin, User, аккаунта, Client. Сценарии подтверждаются отдельно.
- C-04. Контакт обязателен для внутренних CREATED_FROM_TICKET_USER и CREATED_FROM_REQUEST_USER. Действующие разрешённые начальные статусы смены контакта сохраняются. Администратору разрешена смена контакта в ACCEPTED/DEFERRED с синхронизацией TicketUser. Включение сотрудника с отключённым назначенным отделом запрещено до включения отдела либо снятия назначения. Отдел сотрудника нельзя менять, пока он текущий исполнитель.
- C-05. При административной регистрации обращения со слов User первая история внешней TicketUser отражает User. Владелец отверг патч 01 по изменению этого автора. Автор внутренней истории и автор комментария определяются соответствующей операцией. В административных и пользовательских API согласовано строковое представление комментария.
- C-06. Создание отдела должно сохранять переданный enabled, по умолчанию true. Изменение профиля Admin с пропущенным department_id сохраняет отдел; явный 0 снимает при выполнении проверок.
- C-07. Физическое удаление требует отдельного ticket.delete, история удаления не нужна, доступ у ограниченного круга. Отмену отличать от удаления.
- C-08. Сессии. Access JWT 5 минут; refresh 7 суток абсолютного срока от входа с ротацией без продления. Единая БД и один UoW при переходе. При смене пароля, удалении, отключении и повторном включении сотрудника старые refresh отзываются. Выданным access разрешено дожить короткий TTL при смене пароля; фактическая проверка enabled отдельно. При переходе прекратить старые refresh, запросить новый вход и исключить прежний отдельный fallback. При миграции версий заменить NULL на 0, сохранить числовые версии, для новых записей NOT NULL DEFAULT 0. Сверять с выбранным снимком.
- C-09. Идемпотентность. Необязательный ключ для созданий ресурсов, не для отдельно не создаваемых аккаунтов. Пара employee_id + key, fingerprint, тот же результат при повторе, конфликт 409 при изменённом запросе в сроке действия, 24 ч после фиксации. При неопределённом результате важнее сохранить защиту дубля, отложенный отсчёт после сбоя согласован. Сервер не повторяет бизнес-команду; повторяет клиент. Удержание при конкуренции — штатное ожидание/ошибка БД, без отдельного таймера или Retry-After для этой функции. Сверять реализацию, опыты на синтетических данных.
- C-10. Новый scope /execute обсуждён и сохранён как будущее решение. Существующее глобальное ticket.executed, рекомендованы department и own по текущему исполнителю. Сейчас scope проверять только если есть в исходниках. Источник published/docs/futher/ticket_execution_permissions.md.
- C-11. Архитектурные обсуждения. Текущий подход сохраняет ABC репозиториев, SQLite BaseRepository, Gateway и Mapper. Команды, события, outbox и очередь обсуждались как перспектива; оставить явную атомарную синхронизацию пары, рассмотреть фоновые уведомления при конкретной необходимости. Планы по PostgreSQL, async, bootstrap и интеграции см. опубликованные заметки, рекомендации не считать реализацией.
- Только синтетические примеры. README проекта имеет имя readme.md. docs/steps/steps.md содержит пошаговые учебные сценарии и примеры настройки ролей, но подтверждайте их по коду; не переносить учётные данные или исходные JSON из него в результаты. Не выполнять старые демонстрационные запросы как есть.
