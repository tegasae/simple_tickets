# Первичная карта системного аналитика

Для руководства основной источник — опубликованный снимок `1e69ee8`. Локальный `d497e75` с рабочими правками, учебные шаги и отчёты объясняют происхождение решений. Названия профилей заданы владельцем. Код применяет объединение фактически назначенных прав и проверки состояния. ## Шесть профилей

| Профиль | Учебный источник | Как описывать |
|---|---|---|
| Обычный сотрудник | Базовая роль. Шаги, строки 3–21 и 229–246. | Просмотр клиентов, Admin, отделов и заявок. Регистрация внутренней заявки, в том числе обращения со слов User. |
| Инженер | Базовая + роль обычного инженера. Шаги, 33–50 и 250–268. | Работа по собственному действующему назначению, пауза, продолжение, завершение с отправкой на проверку. У учебного профиля есть отдельное право ретроспективной записи по назначенной заявке. |
| Инженер с правом работы на горячей линии | Базовая + инженерная + удалённая по составу примера. Шаги, 85–96 и 293–312. | Рекомендованная заявка своего отдела, самоназначение после принятия, специальный дистанционный старт. По назначенной заявке стартует только её исполнитель. Текстовая подпись учебного сотрудника называет лишь надстройку. |
| Ведущий инженер | Учебный «опытный инженер» с базовой и инженерной ролями. Шаги, 60–75 и 271–290. | Ближайший подтверждённый пример добавляет приём и административное подтверждение результата. Полномочия этих двух действий в коде глобальные. Самостоятельный штатный состав профиля и закрепление за своим отделом требуют решения владельца. |
| Менеджер | Базовая + менеджерская. Шаги, 104–139 и 316–334. | Принимает, меняет данные, планирует и откладывает, отменяет и подтверждает по назначенным правам. Работает с клиентами и их пользователями. Назначение исполнителей и рекомендация требуют отдельных новых прав, которых нет в учебном списке. Просмотр User и назначение их ролей также требуют отдельных прав. |
| Руководитель отдела | Базовая + менеджерская + управление Admin. Шаги, 148–170 и 337–356. | Управляет отделами, внутренними сотрудниками и обоими наборами ролей. Название профиля само по себе область доступа отделом не ограничивает. Право работы инженера и право удаления выдаются отдельно. |

Первое «подтверждение» менеджера или ведущего — приём заявки в работу. Завершение исполнителем переводит её на проверку, после чего результат может подтвердить Admin с отдельным правом или User в связанной карточке. В последнем случае обе карточки получают финальное пользовательское подтверждение. Право отдела/исполнителя на административное подтверждение результата пока запроектировано. ## Различия снимков, влияющие на руководство

| Тема | local | published |
|---|---|---|
| Назначение и рекомендация | Общее право операций с заявками. | Два отдельных диспетчерских права. Самоназначение по праву горячей линии на рекомендованной заявке без чужого действующего назначения. |
| Работа горячей линии | Специальный удалённый старт уже существует. Пауза, продолжение и отправка на проверку требуют обычного права работы. | Для удалённой работы часть этих действий доступна и по одному праву горячей линии с дополнительными условиями. |
| Физическое удаление | Право отмены. | Отдельное право физического удаления. |
| Отключение владельца или контакта | Переход из review в приостановленное состояние отсутствует, синхронизированная внешняя карточка не включается в результат сохранения. | Финальное приостановление из review поддержано, обе карточки возвращаются для сохранения. Активная работа остаётся в процессе. |
| Отключение клиента | Каскад пытается приостановить все открытые карточки. В частности, открытая активная работа может прервать команду недопустимым переходом. | Активную работу и связанную карточку сохраняет, прочие открытые заявки приостанавливает. |
| Данные сотрудника и контакт | Включение Admin не учитывает активность его отдела. Внешнее редактирование контакта ограничено общим правилом карточки. | Включение Admin учитывает состояние отдела. Контакт в связанной паре можно менять и в принятых или отложенных заявках. Для пропущенного отдела при обновлении профиля обе версии используют значение отсутствия отдела. |
| Сессии, повтор отправки, представление | Отдельное хранение refresh, нет опубликованного механизма идемпотентности, обычный комментарий Admin при регистрации со слов User происходил от User. | Общая БД, новые правила сессий и повторов создания, обычный комментарий от Admin при сохранении User как автора начальной внешней записи. |

## Риски и состав руководства

- В обычном старте опубликованная модель принимает признак удалённой работы, а прикладная проверка требует обычного права работы. Владелец согласовал обязательность права горячей линии для дистанционного старта. Объяснить штатный рабочий порядок и отдельно зафиксировать расхождение реализации в материалах проверки.
