# Перекрёстная проверка Python и SQLite

Прочитал независимые карты аналитика, QA и арбитра. Принимаю их разграничение двух realms, связанной пары и трёх разных команд приёма/подтверждения. Матрицу оформляю по учебным наборам и C-12, с отдельно проверенными правами новых диспетчерских операций. Действующий `ticket.executed` глобален, department/own остаются C-10.

- Подтверждаю расхождение C-02. `TicketStartWorkRequest` принимает `work_is_remote=true`; обычный `TicketApplicationService.start_work` требует только `ticket.at_work` и передаёт флаг в `Ticket.start_work`. Доменный валидатор проверяет исполнителя. Отдельный `start_remote_work` проверяет hotline и рекомендацию. При описании штатного пути указываю первый обычный запрос без remote-флага и отдельную команду для горячей линии. Отдельно документирую расхождение и более широкую ветку обычного права для remote-resume. - Подтверждаю расхождение C-06.
