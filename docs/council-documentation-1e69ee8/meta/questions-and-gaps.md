# Вопросы и пределы доказательств

## Разрешено владельцем в текущей задаче

- Основной снимок — ветка GitHub `1e69ee8`, локальные материалы относятся к источникам. Снимки имеют отдельные отпечатки.
- Обычный сотрудник имеет базовый внутренний профиль. Пользователь клиента описан отдельно. Ведущий инженер соответствует прежнему Опытному инженеру.
- Назначение другого исполнителя и рекомендация удалённой работы отнесены к рекомендуемому профилю Менеджера. Руководитель отдела получает набор по назначенным ролям, права из других ролей складываются.
- Рекомендация, указанная сотрудником клиента, не определяет решение о горячей линии. Её ввод следует отключить в будущей версии. Сейчас входное поле принимается и попадает во внутреннюю карточку.

## Вопросы для будущей реализации

1. Следует ли запретить отмечать фактически удалённый способ выполнения в обычной команде старта по назначению, или это допустимая отметка эпизода? Сейчас она доступна по обычному праву работы, а специальная команда горячей линии имеет отдельные ограничения.
2. При отключении рекомендации в клиентском создании сохранить ли поле для переходного периода с игнорированием или отклонять его передачу? Результат влияет на публичный контракт и старые интеграции.
3. Для будущего подтверждения по отделу требуется ли независимый проверяющий для каких-либо профилей? Предложение на будущее трактует право отдела как область, которая включает свою заявку. Глобальное право действует по прежнему контракту.
4. Какие профильные роли и их версии назначены в целевой установке? Подтверждены рекомендуемые рабочие профили. Фактические назначения конкретной рабочей базы в задачу не входили. Для выпуска пользовательских инструкций по динамически настроенной установке их можно сверить штатной инвентаризацией ролей.
5. Детали системного Admin, политику резервного копирования продуктивной базы, восстановление приостановленной заявки и возвращение предыдущего исполнителя следует согласовать при реализации соответствующих инициатив.

## Обнаруженные расхождения и недоступные материалы

- G-01 подтверждён HTTP. В текущем PUT профиля пропущенный отдел становится 0. Владелец ранее утвердил сохранение. При сохранении профиля в работающем выпуске проверять отдел и при необходимости указывать текущий явно.
- G-02 и G-03 имеют разные причины. Специальная команда горячей линии проверяет своё право и рекомендацию, обычная команда принимает отметку эпизода, клиентское создание принимает начальную рекомендацию. Инструкция для сотрудников описывает решение Менеджера.
- Учебные роли и старые описания процессов не устанавливают полномочия установленной БД. Ссылки на пользовательские шаги даны на уровне действия. Конкретные кнопки и сообщения интерфейса не проверялись.
- Полный архив внешних переписок, конфигурация реальной установки, фактические роли работников, рабочие базы, .env, фронтенд и его архивы не исследовались. Сведения о намерениях ограничены доступным обсуждением, репозиторными заметками и ответами владельца.
- OpenAPI и статическая трассировка охватывают все собственные маршруты и модели выбранного снимка. Щадящий синтетический прогон подтверждает только зафиксированные сценарии. Серверные версии вне этой среды, нагрузка, обновление рабочей БД, восстановление из резервной копии и переход на PostgreSQL отдельно не испытывались.
