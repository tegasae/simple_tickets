## Резюме

Некоторые заявки после принятия клиентского обращения находятся в:

```text
ACCEPTED
```

При этом исполнитель ещё не назначен.

Часть инженеров должна мониторить такие заявки и может самостоятельно попытаться выполнить их удалённо.

---

### 1. Не любую ACCEPTED-заявку можно брать в работу

Нельзя разрешать общий переход:

```text
ACCEPTED → AT_WORK
```

для всех заявок.

Иначе любой инженер, имеющий право работать с `Ticket`, сможет взять любую принятую, но ещё неназначенную заявку.

Поэтому у `Ticket` должен быть отдельный признак:

> эту заявку разрешено брать непосредственно из `ACCEPTED` для удалённого выполнения.

В существующей модели уже есть:

```python
is_remote
```

Если его текущий смысл близок к этому, новое поле вводить не требуется. Нужно только чётко определить его семантику.

Возможно, более точный смысл:

```text
remote candidate
remote allowed
```

то есть не «заявка сейчас выполняется удалённо», а:

> заявку разрешено попытаться выполнить удалённо.

---

### 2. Удалённая заявка может перейти напрямую в AT_WORK

Для заявки с соответствующим признаком:

```text
ACCEPTED
→ AT_WORK
```

разрешён прямой переход.

Отдельный `ASSIGNED` здесь не нужен,
