# Simple Tickets — Frontend сотрудников

React/Vite frontend для актуального Simple Tickets API.

## Что реализовано

- Вход / выход сотрудника (backend Admin realm).
- Автоматический refresh `access_token` через `POST /auth/admin/refresh`.
- При нескольких одновременных `401` выполняется только один refresh; исходные запросы повторяются один раз после его успеха.
- При неуспешном refresh локальная сессия очищается и пользователь возвращается на login.
- Четыре темы: **1С 8.3**, **Классика**, **Футуризм**, **Barbie**.
- Permission-aware навигация и скрытие недоступных операций.
- Разделы: **Заявки**, **Клиенты**, **Пользователи**, **Сотрудники**, **Отделы**, **Роли**.
- Карточка клиента содержит его User и переход к заявкам клиента.
- Карточка User содержит переход к его заявкам.
- Заявки: Все / Открытые / Закрытые / Назначенные мне / Рекомендовано удалённо.
- Frontend-поиск и комбинированные фильтры заявок.
- Обязательные колонки: №, клиент, отдел, первые 50 символов текста, план, статус, срочность, назначенный исполнитель, последний актуальный исполнитель, затраченное время.
- Создание Ticket одной формой: при `user_id > 0` backend сам создаёт связанный `TicketUser`.
- Карточка Ticket показывает доступные **действия**, а не select статусов.
- Реализованы текущие endpoint-ы accept/reject/defer/assign/start-work/start-remote-work/pause/resume/finish/retroactive/execute/cancel и редактирование данных заявки.
- История статусов и обычные комментарии разделены.

## Запуск

Требуется современный Node.js.

```bash
npm install
npm run dev
```

По умолчанию frontend обращается к `/api/*`. Vite proxy отправляет эти запросы на:

```text
http://127.0.0.1:8000
```

Другой backend можно указать:

```bash
BACKEND_BASE_URL=http://127.0.0.1:9000 npm run dev
```

Либо изменить `VITE_API_PREFIX` через `.env`.

## Production build

```bash
npm run build
```

Результат будет в `dist/`.

## Важные договорённости

Backend остаётся источником истины для permissions, workflow и бизнес-валидации. Frontend скрывает заведомо недоступные действия, но не заменяет backend-проверки.

После успешной Ticket-операции карточка заменяется целиком на новый `TicketResponse`, возвращённый backend.

Пока в `TicketResponse` нет `current_status`, frontend определяет его по последней записи `statuses`. Поля `current_executor_id` и `last_executor_id` уже используются напрямую и могут быть равны `0`. Для представления «Назначенные мне» используется `/admin/tickets/by-executor/{executor_id}`.
