# Правила интерфейса Admin

Интерфейс продолжает полезные паттерны frontend v2. Стили и общие компоненты проверяются по реальным сценариям. Рабочие вкладки, доступная таблица, диалог и подбор из справочников проектируются под задачи v3. [Анализ v2](USABILITY_ANALYSIS.md) · [DEC-011, DEC-012, DEC-014](DECISIONS.md)

## Иерархия и визуальная организация

- Название страницы, состояние и основное доступное действие читаются первыми. В очередях это «Новая заявка», в карточке — следующий допустимый шаг. Редкие действия находятся в подписанном меню или секции. Удаление и отмена различаются названием, результатом и подтверждением.
- Использовать знакомые CSS-токены v2 после проверки контраста и плотности. Один основной шрифт, различимые уровни заголовков, числа с устойчивой шириной в колонках дат и номеров, читаемый перенос длинного текста. Цвет дополняет текст статуса. Одиночная иконка требует понятного доступного имени.
- На широком экране уместна плотная таблица и две группы реквизитов. На узком экране первыми остаются номер, тема, статус и основное действие. Дополнительные данные переходят ниже или в раскрываемый блок. Внутренний скролл таблицы сохраняет доступ к ячейкам, панель действия не закрывает фокус.
- Переиспользуемые паттерны одинаковы по контекстам. Команды «Сохранить», «Добавить комментарий», «Взять в работу» называют результат действия. Поля получают устойчивые русские подписи. Служебные коды разрешений показывать только там, где они помогают оператору ролей.

## Очередь заявок

1. Всегда видимы название очереди, строка поиска, «Найти», «Фильтры» и активные условия. Enter применяет поисковый текст. Номер, доступный текст заявки, русская подпись и код статуса входят в основной поиск. Условия по справочнику работают только на разрешённых данных. «Сбросить фильтры» доступно в раскрытом блоке, убрать одно условие можно рядом с его меткой.
2. Расширенные фильтры предлагают статус, срочность, отдел, клиента, заявителя, контакт и исполнителя, если соответствующие данные доступны. Выбор клиента ограничивает подбор пользователя и контакта. После изменения условий показать точный счётчик и начать с первой страницы.
3. Основные столбцы — номер, тема, статус, «Дата создания», клиент и исполнитель. По потребности показать отдел, приоритет, план, последнее назначение и длительность. «Дата создания» берётся из первого события, неизвестная дата обозначается «—». Предложенный порядок по умолчанию — дата по убыванию, затем ID по убыванию. Пустые даты находятся в конце. Даты сравниваются как время, номера как числа, русские названия по локали, статус по согласованной группировке. Сортировка применяется ко всему отображаемому набору до пагинации с явным индикатором направления.
4. Пагинация показывает страницу, число результатов и кнопки перехода. Настройку размера страницы и видимости вторичных столбцов можно сохранить по очереди. Закрепление заголовка допустимо, пока он не перекрывает клавиатурный фокус. Настраиваемые столбцы вторичны относительно читаемого состава по умолчанию.
5. Открытие строки использует ссылку номера или темы. Команды карточки зависят от актуального статуса и прав. После мутации обновляются затронутые списки. При возврате от карточки восстановить очередь, фильтры, страницу, прокрутку и фокус. Если строка ушла из выборки, сохранить контекст и дать переход к ней из сообщения об изменении или к ближайшей строке при возврате.

В «Горячей линии» рекомендация является признаком, а не этапом workflow. Подпись «Рекомендовано для горячей линии» относится к признаку. Предлагаемая кнопка «Взять в работу на горячей линии» переводит допустимую заявку в `AT_WORK` одним запросом. «Взято в работу на горячей линии» подтверждает результат. Фактический способ работы представлен в истории. [J-010](USER_JOURNEYS.md) · [DEC-003, DEC-009](DECISIONS.md)

## Карточки и формы

В карточке заявки закрепить номер, тему, статус и доступное основное действие. Затем отображать описание, отдел, исполнителя, приоритет и план в зависимости от права и состояния. Нередактируемые реквизиты и служебные связи доступны ниже. Связанные клиент и лица имеют понятный возврат в исходную заявку. «Комментарии» открываются по умолчанию, рядом находится «История». Свободный комментарий вводится на месте. Причина отказа, отложения или отмены вводится в соответствующем действии.

| Форма | Поля, порядок и ограничения |
|---|---|
| Вход | Логин, пароль, «Войти». Подписи остаются видимыми. Поддерживаются вставка и менеджеры паролей. Ошибка входа связывается с формой. |
| Новая заявка | Клиент и текст обязательны. Затем заявитель и контакт в пределах клиента, активный отдел, описание, срочность, план, комментарий и рекомендация по праву. При смене клиента сбрасываются связанные выборы с уведомлением. Серверные длины и типы определяют валидацию. |
| Рабочие поля заявки | Редактируются допустимые поля. Перенос изменения отдела и срока в рабочую область зависит от доступного действия. Архивный отдел остаётся указан с пометкой, новый выбирается из активных. При назначении предлагаются только действующие сотрудники подходящего отдела. |
| Переход статуса | Показать новый этап, требуемый комментарий и исходный контекст. Для ретроспективной записи подписи явно различают начало, окончание и длительность. Подтверждение зависит от последствий и риска. |
| Справочники | Группы «Основное», «Контакты», «Аккаунт» и «Роли» по правам и сущности. Требования валидации берутся из контракта. Просмотр, изменение профиля и операции с аккаунтом показывают разные состояния. |
| Назначение ролей | Контур Admin и User виден в заголовке. Показывать текущие и предлагаемые изменения, объяснить недоступность каталога, перечитать результат при частичном изменении. Операции назначения отделены от сохранения профиля. |

Большие справочники используют подписанный combobox с доступным подбором. Показывать введённый запрос, выбранное значение, загрузку, пустой набор и неполную доступность. Значение передаётся по ID. Совпадающие имена различаются доступным уточнением. У необязательного поля есть явная очистка. Другая организация не появляется в подсказках контакта текущего клиента.

Валидацию показать рядом с полем или в сводке, ведущей к полям. После ошибки сохранить корректный ввод, фокус переводить к месту требуемого изменения осмысленно. На время отправки заблокировать повтор этого действия и показать ход операции. После подтверждённого сохранения очистить только отправленный черновик. Для неожиданного обновления использовать сведения о видимых изменившихся полях и локальный baseline. Контракт заявки не даёт клиенту версию или If-Match для гарантированной защиты от перезаписи. [J-005, J-007, J-013](USER_JOURNEYS.md) · [Контракт](API_CONTRACT.md)

## Диалоги и несохранённый ввод

Модальный слой подходит подтверждению, краткому вводу и форме, требующей фокуса. Рабочие карточки остаются документами или панелями. Клик по фону сохраняет слой. Escape закрывает верхний слой или список подсказок, после чего фокус возвращается к исходному элементу. В изменённой форме закрытие вызывает подтверждение с возможностью вернуться. Закрытие рабочей вкладки и выход отмечают несохранённый ввод. Полное обновление страницы восстанавливает сессию по согласованной модели. Черновик в памяти страницы может исчезнуть, поэтому активное редактирование получает доступное браузеру предупреждение.

## Состояния и обратная связь

| Состояние | Отображение и следующее действие |
|---|---|
| Первичная загрузка | Показать заголовок страницы, короткий текст «Загружаем …» и статус для экранного считывателя. |
| Обновление существующих данных | Оставить разрешённый список и положение пользователя, пометить обновление. Применить только актуальный ответ. |
| Пустая очередь | Объяснить отсутствие записей этой очереди, предложить доступное действие. |
| Пустой результат поиска | Показать применённые условия, сброс или изменение запроса. |
| Частично недоступные данные | Сохранить читаемую карточку, показать ID или причину у справочника, дать повтор загрузки. |
| Успех мутации | Подтвердить результат с предметом действия. Показать номер новой заявки и ссылку при праве чтения, изменение статуса или применённые роли. |
| Ошибка поля 400/422 | Объяснить правило и шаг исправления, удержать ввод. |
| Недействительный вход 401 | Запустить допустимое восстановление, при подтверждённой недействительности показать вход с причиной. |
| Недостаточно прав 403 | Показать причину и доступный возврат. Смена прав меняет доступные команды. |
| Не найдена запись 404 | Оставить контекст и дать переход к доступному списку или родительской заявке. |
| Конфликт 409 или изменившийся переход | Перечитать снимок, объяснить новое состояние и сохранить черновик для осознанного решения. |
| Сбой сети или 503 | Сохранить ввод, показать «Повторить» для чтения. При неопределённом результате мутации проверить состояние или применить поддерживаемый идемпотентный повтор. |
| Длительная команда | Показывать ход операции у запускающего элемента, защищать от повтора и от устаревшего ответа. |

Короткие уведомления дополняют устойчивое сообщение у проблемной формы. Итог должен быть понятен и после исчезновения уведомления. [Доступность](ACCESSIBILITY.md) · [Ошибки backend](../../src/web/main.py#L60)
