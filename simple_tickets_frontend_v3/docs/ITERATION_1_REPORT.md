Модель I1 использует access в памяти и ротируемый refresh в `sessionStorage`. Одновременные 401 делят одну ротацию, чтение повторяется один раз, более позднее истечение допускает новую ротацию. GET заявок с подтверждённым 403 закрывает данные до ручной перепроверки. При выходе старые ответы не восстанавливают прежний экран. После потери ответа ротации клиент может подтвердить локальный выход, а серверный отзыв остаётся неподтверждённым. [Аутентификация](AUTHENTICATION.md).

Сохранены React и React DOM 19.2.8, Vite 8.1.5 и plugin-react 6.0.4. Установка проверена на Node 24.22.3 и npm 11.19.1. Дополнительных npm-зависимостей в runtime нет. Для тестов используются встроенный `node:test` и предустановленные инструменты Python/Chromium. Как именно адаптированы HTML, форма входа, оболочка, таблица, история, форматтеры и CSS v2, указано в [таблице переноса](CODE_REUSE_PLAN.md#6-фактическая-адаптация-в-i1).

## Область изменений и дальнейшая работа

Код, конфигурация, тесты и документация находятся внутри `simple_tickets_frontend_v3/`. Git-проверка сверяет `src/`, v2, `AGENTS.md`, конфигурацию Codex и остальные пути с исходной ревизией. Временные результаты тестов и сборки исключены правилами v3. Изменения представлены в рабочем дереве для приёмки.

I2 включает несколько рабочих карточек, связанные сущности, создание и изменение разрешённых полей, комментарии. После I1 владелец утвердил объём и модель черновиков в DEC-012/025. Для приёмки I2 потребуются отдельные синтетические данные для записи, проверки сохранения черновиков, обработки 422 и неизвестного результата сохранения.
