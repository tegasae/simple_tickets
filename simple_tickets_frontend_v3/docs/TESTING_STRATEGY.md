## Трассировка и критерии приёмки

У каждого функционального требования `FR-001`–`FR-019` есть проверяемые критерии в [функциональных требованиях](FUNCTIONAL_REQUIREMENTS.md). Номер `TC` совпадает с номером `FR`. У теста фиксируются исходная роль и права, состояние и идентификаторы сущностей, действие, сетевой результат и ожидаемое состояние интерфейса. В отчёте о прогоне указываются `FR`, `TC`, ревизии frontend и backend, тестовый профиль, результат и ссылка на доказательство. Условные сценарии исполняются после согласования соответствующего решения.

Два параллельных `401` приводят к одному refresh на поколение сессии, повтор ограничен одним. | `TC-007` → `FR-007` · создание и редактирование | Обновить варианты заявителя и контакта при смене клиента, отклонить поздний ответ прежнего клиента. При доступе только на создание и чтение нужного справочника отдельная форма работает, после 201 показан номер без ссылки на недоступную карточку. | Компонентный, контракт, E2E |

## Сквозные условия безопасности и надёжности

- Сценарии утверждённого `DEC-010` включают повторный вход после недействительного refresh и автоматическое восстановление обычного reload при действующей сессии. Refresh в `sessionStorage` доступен JavaScript и может скопироваться при дублировании вкладки. Проверять один одновременно выполняющийся refresh внутри поколения, последовательные ротации, запоздалые ответы, очистку данных и logout с актуальным refresh. `503` и потеря сети дают временный отказ. `403` не запускает refresh. При отказе чтения заявки локальное `ticket.view` и прежний экран закрываются до успешной проверки прав. [Сессии](AUTHENTICATION.md) · [Ротация backend](../../src/web/auth/services/shared_sessions.py)
- Перед рискованным изменением предварительное чтение может обнаружить расхождение, а серверное состояние может измениться между запросами. Контракт Admin `TicketResponse` не возвращает `version`; гарантия условной записи через `If-Match` не установлена. После неопределённого ответа мутации перечитать состояние. Для конкурентного старта проверить `400` при изменившемся состоянии, `409`, когда сработал optimistic lock, и `503` при временной ошибке. Критерий — сохранённое состояние и история, а не один обязательный код проигравшей попытки. [Модель ответа](../../src/web/models/tickets.py) · [Маппинг ошибок](../../src/web/main.py)
- Проверить идемпотентное создание или комментарий с повтором одного ключа, конфликт того же ключа с изменённым запросом и сохранность данных при повторе после commit. За пределами TTL старый ключ не обещает восстановление той же операции. Для произвольных мутаций в `DEC-017` нет автоматического повторения после неопределённого сетевого исхода. [Идемпотентность](../../src/web/idempotency.py) · [Регрессия комментариев](../../tests/test_creation_operation.py)
- По `NFR-004` до приёмки использовать согласованные типичный и пиковый наборы. Измерять время загрузки списка и карточки, смены фильтра и переключения рабочих вкладок, объём передаваемых данных и отзывчивость на согласованном устройстве. Отдельно фиксировать вклад браузера и API. Желательные численные пределы остаются предложениями до согласования. [Нефункциональные требования](NON_FUNCTIONAL_REQUIREMENTS.md)

## Definition of Ready и Definition of Done

Задача готова к реализации, когда цель, `FR`/`NFR`, критерии приёмки и проверка `TC` указаны, подтверждены API и минимальные права, согласованы пользовательский сценарий и относящиеся к задаче архитектурные решения, известны путь изменений, зависимости и существенные риски. Открытый вопрос считается блокером только для задач, от которых зависит его решение. Программная реализация требует отдельного разрешения. Изменение backend не входит в готовую задачу. [План и backlog](IMPLEMENTATION_PLAN.md)

Задача завершена при выполнении критериев приёмки, проверке реальных контрактов в предусмотренном объёме, прохождении нужных тестов и сборки, проверке ошибок, прав и доступности, независимом ревью и устранении критических замечаний. `FR`/`NFR`, `DEC`, `TC` и backlog должны оставаться согласованными. Отсутствующую проверку фиксировать как невыполненную с причиной и влиянием на готовность. Внешние каталоги защищены в проверке Git и в конфигурации тестовой среды.

По `DEC-016` первый вертикальный срез подтверждается входом Admin, загрузкой прав, восстановлением входа по согласованной схеме, просмотром списка и карточки, отказом без `ticket.view` и корректной обработкой загрузки, пустого списка и API-ошибок. Проверки среза используют `TC-001`–`TC-004` и применимую часть `TC-014`. Мутации, отдельная очередь проверки и финальная подпись действия горячей линии не влияют на приёмку этого среза.

## Готовность к эксплуатации

- Сборка из зафиксированных версий воспроизводима. На релизном тестовом стенде проверены разрешённые API, изоляция базы, подключение по HTTPS, настройка same-origin маршрута и согласованный план контроля ошибок без записи чувствительных данных.
- Все обязательные требования первой поставки трассируются к успешным проверкам. Политики сессии и доступа согласованы, E2E проверяет действующие профили Admin и отказ без прав, пройдены регрессии конкурентных мутаций и восстановления. Открытые критические дефекты по доступу, потере данных или ключевому сценарию блокируют выпуск.
- Выполнены ручные и автоматизированные проверки согласованного объёма `DEC-014`, проверка работы на репрезентативной нагрузке, проверка пользовательских задач с представителями ролей и независимый review. Неизвестные целевые данные и непроверенные критерии указаны в релизном отчёте.
- До и после работ зафиксированы `HEAD`, staged/unstaged, неотслеживаемые и игнорируемые выходы. Сверены оба пути переименований, удаления и изменения относительно базы. Релизный тестовый стенд использует доступ к защищённым исходникам только для чтения, тестовые SQLite, логи и отчёты находятся вне защищённых каталогов. На этапе проектирования изменения ограничены `simple_tickets_frontend_v3/docs/`.

Порядок эксплуатации, оставшиеся продуктовые условия и статус начала реализации описаны в [статусе проекта](PROJECT_STATUS.md). Это критерии будущей проверки. Успешные прогоны, сборка и эксплуатационная готовность пока не установлены.
