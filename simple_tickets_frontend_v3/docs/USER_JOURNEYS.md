# Пользовательские сценарии Admin

Идентификатор J-nnn связан с FR-nnn. Названия рабочих категорий используются для приёмочных сценариев. Доступ определяется фактическими разрешениями, а не названием должности. Первая вертикаль проектируется для входа, восстановления сессии, прав, списка и карточки на чтение, включая состояния ошибок в этих сценариях. Разделы ниже задают поведение и для последующих итераций. [Требования](FUNCTIONAL_REQUIREMENTS.md) · [Матрица прав](PERMISSIONS_MATRIX.md) · [План](IMPLEMENTATION_PLAN.md)

## J-001 — Войти, восстановить вход, выйти

- **Цель и старт.** Admin открывает приложение без входа либо обновляет страницу с действующей сессией. Идентификация выполняется через контур Admin.
- **Шаги.** Войти логином и паролем через `POST /auth/admin/login` с form-urlencoded. При обновлении и наличии сохранённого refresh сначала показать «Восстанавливаем вход…», выполнить `POST /auth/admin/refresh`, сохранить актуальную пару по выбранной модели хранения и получить права. Затем открыть разрешённый исходный маршрут или доступный раздел. «Выйти» вызывает `POST /auth/admin/logout` и закрывает рабочую сессию.
- **Ошибка и альтернатива.** Недействительные данные входа показываются в форме. Недействительная сессия ведёт к повторному входу с объяснением. При временной недоступности показать повтор и возможность выйти. После локального выхода поздний ответ не восстанавливает прежнюю сессию.
- **Успех.** Обычное обновление с действующей сессией возвращает к разрешённой странице без повторного пароля. Выход завершает доступ к рабочей области, кэшу и черновикам. Если отзыв сессии на сервере не подтверждён, UI различает это с локальным выходом. [DEC-007, DEC-010](DECISIONS.md) · [Аутентификация](AUTHENTICATION.md) · [Роутер](../../src/web/routers/auth.py)

## J-002 — Открыть разрешённый раздел

- **Старт.** Admin вошёл, открывает меню или прямую ссылку.
- **Шаги.** Получить `GET /admin/admins/permissions`, показать разрешённые разделы. Проверить страницу и доступность действий по правам, выполнимости перехода и отношению сотрудника к сущности. Повторно проверять серверный ответ при каждом действии.
- **Ошибка и успех.** При 403 объяснить недоступность и дать возврат к доступному разделу. При ошибке загрузки прав сохранить состояние ошибки с повтором. Успех — набор команд соответствует правам и раздельно контролирует чтение и операции. [Матрица прав](PERMISSIONS_MATRIX.md) · [Admin permissions](../../src/web/routers/admin/admins.py#L117)

## J-003 — Найти и открыть заявку

- **Старт.** Admin с `ticket.view` открывает очередь.
- **Шаги.** Получить список через `GET /admin/tickets/`, открытую или закрытую выборку `/open`, `/closed`, либо назначенные заявки через `/by-executor/{executor_id}`. Ввести номер, строку или статус, нажать «Найти» или Enter. При необходимости раскрыть дополнительные фильтры. Применить их к полученному набору, затем сортировку и пагинацию. Открыть карточку ссылкой номера.
- **Ошибка и альтернатива.** Пустой список даёт обновление или создание при праве. При пустом поиске показать активные условия и предложить их очистить. Сбой загрузки даёт повтор. При недоступном справочнике не обещать совпадение по имени, если разрешены только ID.
- **Успех.** Поиск по русскому названию статуса и его коду даёт согласованные результаты. Изменение фильтра сбрасывает страницу. Сортировка влияет на весь доступный результат. Возврат восстанавливает очередь, условия, прокрутку и фокус. Предложенный параметр `queue` восстанавливает разрешённую очередь из URL, а условия со свободным текстом остаются в памяти текущей сессии. [Навигация](INFORMATION_ARCHITECTURE.md) · [Интерфейс списка](UI_GUIDELINES.md) · [Ticket queries](../../src/web/routers/admin/tickets.py#L123)

## J-004 — Прочитать карточку и историю

- **Старт.** Разрешённый Admin открывает строку либо URL заявки.
- **Шаги.** Получить `GET /admin/tickets/{ticket_id}`. Показать номер, тему, текущий статус по последней записи истории, «Дата создания» по `statuses[0].date_created`, описание, служебные поля, комментарии первой вкладкой и историю следующей. Схему чужих связанных данных заполнять разрешёнными именами либо ID.
- **Ошибка и успех.** 404 и 403 имеют понятный возврат. При неполной истории неизвестная дата обозначается «—». При partial loading видна карточка, а недоступный справочник имеет собственное состояние. Успех — начальные статусы подписаны как «Создана», «Создана по запросу клиента», «Создана из заявки клиента». [DEC-005, DEC-006](DECISIONS.md) · [TicketResponse](../../src/web/models/tickets.py#L243)

## J-005 — Вести несколько заявок

- **Старт.** Открыта первая заявка, пользователь сохраняет незавершённый ввод в рабочей вкладке.
- **Шаги.** Открыть вторую через список по J-003 и изменить её независимо. Вернуться одним переключением. При закрытии изменённой вкладки предложить продолжить редактирование, отбросить черновик или сохранить его, если доступна отправка. Вкладку заявки по тому же ID активировать повторным открытием.
- **Ошибка и успех.** Запоздалый ответ карточки не переключает вкладки и не заменяет черновик. Если получена свежая серверная версия, выделить изменившиеся значения и предложить применить черновик осознанно. Успех — два черновика и внутренние разделы сохраняются при переключении. Сохранение черновика при полном обновлении страницы требует отдельной модели хранения. [DEC-004, DEC-012](DECISIONS.md) · [Навигация](INFORMATION_ARCHITECTURE.md)

## J-006 — Проверить клиента, заявителя или контакт

- **Старт.** Открыта заявка, у Admin есть соответствующие права по матрице.
- **Шаги.** Открыть связанный объект как дочерний контекст. Чтение — `GET /admin/clients/{client_id}` с `client.view` или `GET /admin/users/{employee_id}` с `user.view`. Сверить данные. Нажать «К заявке №…» или Back.
- **Ошибка и успех.** Недоступный или удалённый объект обозначить у ссылки либо в панели с действием возврата. Первоначальная карточка и её черновик сохранены. После возврата доступен исходный раздел и восстановлен фокус. [Схемы](WIREFRAMES.md) · [Клиенты](../../src/web/routers/admin/clients.py) · [Пользователи](../../src/web/routers/admin/users.py#L168)

## J-007 — Создать заявку или изменить разрешённые поля

- **Старт.** Для создания есть `ticket.created` или `ticket.operation` и доступ к обязательному каталогу клиентов. В I2 форма доступна через `/tickets/new` и из оболочки независимо от `ticket.view`. Для редактирования обрабатываются отдельные права и допустимое состояние согласно контракту. Установка рекомендации требует `ticket.set_remote_recommendation`.
- **Шаги.** Открыть форму. Выбрать активного клиента, ввести текст. При необходимости выбрать заявителя и контакт из пользователей этого клиента, активный отдел, срочность, план, описание, комментарий и рекомендацию. Каталоги через `GET /admin/clients/`, `/admin/users/client/{client_id}`, `/admin/departments/` с соответствующим правом чтения. Создание выполняет `POST /admin/tickets/`. Редактирование использует PATCH `/admin/tickets/{id}/description`, `/contact-user`, `/department`, `/remote-work-recommended`, `/urgency`, `/schedule`, а снятие плана — DELETE `/schedule`.
- **Ошибка и альтернативы.** При смене клиента сбросить зависимые поля с сообщением. Ошибки 400/422 и устаревший справочник показывать рядом с полем, ввод удерживать. При 403 каталога сообщить об отсутствии права выбора. Для обязательного поля объяснить, почему отправка недоступна. При временном сбое предложить повтор загрузки, при пустом доступном каталоге показать отсутствие подходящих вариантов. После неоднозначного ответа создания поддержанный повтор использует прежний ключ и тот же payload. При изменении данных сначала проверить серверный снимок.
- **Успех.** Видно сообщение с номером созданной заявки и ссылкой при наличии `ticket.view`. Если действующий фильтр скрывает заявку, явно указать причину. Правка подтверждается серверным снимком, остальные вкладки сохраняют свои черновики. [UI форм](UI_GUIDELINES.md) · [Схемы](../../src/web/models/tickets.py#L28) · [Изменение полей](../../src/web/routers/admin/tickets.py#L442)

## J-008 — Добавить комментарий

- **Старт.** Открыта карточка и есть `ticket.operation` и допустимое состояние для добавления.
- **Шаги.** Во вкладке «Комментарии» набрать текст в подписанном поле рядом с кнопкой «Добавить комментарий». Отправить `POST /admin/tickets/{id}/comments` с `comment` длиной 1–1000 после удаления пробелов по краям и с ключом операции в выбранной модели транспорта. Ввод очищается после подтверждения. Комментарий к переходу статуса вводится в контексте перехода.
- **Ошибка и успех.** При ошибке показать причину у поля и сохранить текст. Успех — комментарий доступен без перехода в отдельное окно. При идемпотентном ответе предыдущего снимка перечитать карточку, чтобы сохранить свежие данные. [Комментарии](../../src/web/routers/admin/tickets.py#L407) · [Идемпотентность](../../src/web/idempotency.py)

## J-009 — Принять, назначить и вести работу

- **Старт.** Диспетчер или исполнитель открыл актуальную карточку. Разрешение и статус проверяются для каждого действия. Полная матрица переходов находится в контракте.
- **Шаги.** Принять через `PATCH /admin/tickets/{id}/accept`. Для отклонения или отложения указать причину, отправить `/reject` или `/defer`. Для назначения другого сотрудника с `ticket.assign_executor` выбрать активного сотрудника того же отдела из доступного каталога и отправить `/executor`. Начать, приостановить, продолжить или закончить работу через `/start-work`, `/pause-work`, `/resume-work`, `/finish-work`. Для ретроспективной регистрации допустимой работы ввести время и режим по контракту `/complete-work-retroactively`.
- **Ошибка и успех.** Недоступный каталог даёт конкретную причину и повтор. При наличии каталога выбор ограничен допустимыми сотрудниками. Для обязательной причины объяснить правило перед отправкой. При конфликте обновить состояние, сохранить ввод и пересчитать допустимые кнопки. Успех — список и карточка отражают новый статус и исполнителя. [API](API_CONTRACT.md) · [Workflow](../../src/web/routers/admin/tickets.py#L686) · [Назначение](../../src/domain/services/ticket_service.py#L254)

## J-010 — Взять рекомендованную заявку в работу на горячей линии

- **Старт.** Заявка рекомендована, есть `ticket.at_work_remote`. Для исходного `ACCEPTED` сервер проверяет активного Admin, положительный совпадающий отдел. Для `ASSIGNED` требуется уже назначенный текущий исполнитель.
- **Шаги.** Из очереди «Горячая линия» или карточки нажать предлагаемую кнопку «Взять в работу на горячей линии». Выполнить один `PATCH /admin/tickets/{id}/start-remote-work` с JSON-объектом `{}` либо с `comment`. Блокировать дублирующий клик до результата. Ответ `AT_WORK` обновляет карточку и очередь.
- **Ошибка и успех.** Когда выбор проверяем только сервером, объяснить причину отказа, после бизнес-конфликта перечитать карточку. Одновременная попытка другого сотрудника не повторяется автоматически. Успех подтверждается текстом «Взято в работу на горячей линии», а исполнитель и статус отвечают серверу. [DEC-003, DEC-009](DECISIONS.md) · [Роутер](../../src/web/routers/admin/tickets.py#L852) · [Операция](../../src/application/services/ticket_service.py#L710)

## J-011 — Проверить готовую заявку

- **Статус проекта.** Отдельная очередь Admin «На проверку» предложена, решение ожидает согласования. [DEC-008](DECISIONS.md)
- **Старт и шаги.** С `ticket.view` открыть очередь. В выборке `GET /admin/tickets/open` оставить заявки с последним статусом `READY_FOR_REVIEW`. Открыть нужную карточку, оценить актуальный результат и историю. С `ticket.executed` отправить `PATCH /admin/tickets/{id}/execute` по разрешённому переходу.
- **Ошибка и успех.** Admin без права завершения может прочитать карточку при `ticket.view`. При перемещении заявки в другой статус из-за одновременной работы объяснить состояние и предложить обновление. После `EXECUTED` строка уходит из очереди, карточка показывает результат. Подтверждение клиентом относится к контуру User и находится вне первого релиза. [DEC-002](DECISIONS.md) · [Маршрут](../../src/web/routers/admin/tickets.py#L1020)

## J-012 — Вести административные справочники

- **Старт.** Admin выбирает клиенты, пользователи, сотрудники или отделы с соответствующим правом чтения. Изменения проверяются на отдельные права.
- **Шаги.** Открыть список, найти строку, просмотреть или изменить профиль и состояние. Каталоги — `GET /admin/clients/`, `/admin/users/`, `/admin/admins/`, `/admin/departments/`. Создание, редактирование, операции с аккаунтом и включение или отключение вызывают ровно соответствующий метод из API. Права на изменение состояния клиента отдельно от контактных данных. Формы аккаунта и пароля показывают своё действие и статус.
- **Ошибка и успех.** Удерживать текст профиля при ошибке поля, отделить истёкшие права от недоступности каталога. Конфиденциальные поля, включая пароль, очищать при закрытии формы и смене сессии. После сохранения перечитать зависимые связи, обновить строку и вернуть доступный фокус. [API](API_CONTRACT.md) · [Права](PERMISSIONS_MATRIX.md)

## J-013 — Назначить или снять роль

- **Старт.** Право `role.assign` открывает действия для Admin, `role_user.assign` для User. Чтение соответствующего профиля требует своего права.
- **Шаги.** Открыть вкладку ролей нужного контура. Загрузить `GET /admin/roles/admin` либо `/admin/roles/user`. В профиле открыть отдельную область назначения, выбрать изменения с понятной разницей и подтвердить. Использовать POST/DELETE `/admin/admins/{id}/roles` или `/admin/users/{id}/roles`. Каталог поддерживает просмотр, создание и допустимое удаление. Прямое изменение определения роли отсутствует в API.
- **Ошибка и успех.** При частичном результате по нескольким вызовам перечитать профиль, показать применённые и неприменённые шаги. Без каталога объяснить сбой или право, сохранять подтверждённые назначения. После изменения собственных назначений перечитать `GET /admin/admins/permissions` и обновить доступные команды и данные. Успех — профиль отражает серверный итог, несохранённые поля профиля сохранены в их черновике в пределах актуальных прав. [DEC-015](DECISIONS.md) · [Роли](../../src/web/routers/admin/roles.py) · [Admin assignments](../../src/web/routers/admin/admins.py#L327) · [User assignments](../../src/web/routers/admin/users.py#L338)

## J-014 — Восстановиться после ошибки

- **Старт.** Загрузка, мутация или восстановление входа завершается неожиданно.
- **Шаги.** Для 401 определить возможность refresh, для подтверждённо недействительной сессии перейти ко входу. 403 оставляет понятную причину доступа. 404 у карточки даёт возврат. 400/422 связывают подсказку с действием или полем. После 409 или доменного отказа о состоянии перечитать сущность. При 503 и сбое сети предложить повтор чтения. Для неопределённого результата мутации сохранить ввод и проверить серверное состояние.
- **Результат.** Пользователь видит, подтверждена ли операция, что можно сделать дальше и куда обратиться. Черновик сохраняется в действующей сессии. Ответ старой сессии, старой карточки или старого запроса не перезаписывает текущий интерфейс. [Состояния UI](UI_GUIDELINES.md) · [HTTP-ошибки](../../src/web/main.py#L60)

## J-015 — Отменить или удалить запись

- **Старт.** Admin имеет отдельное право и допустимое состояние. Отмена заявки требует `ticket.canceled`, физическое удаление — `ticket.delete`. Удаление системной или назначенной роли отклоняет сервер.
- **Шаги.** Для отмены заявки указать причину и применить `PATCH /admin/tickets/{id}/cancel`. Для физического удаления выбрать однозначно названную команду. Диалог показывает сущность, последствие для заявки и связанных данных, безопасный выход и «Удалить …». После подтверждения вызвать соответствующий DELETE, для заявки это `/admin/tickets/{id}`.
- **Ошибка и успех.** Успех отмены оставляет карточку и историю, а очередь обновляется по итоговому статусу. Успех физического удаления с `204` убирает запись из доступного набора и возвращает фокус к следующему действию. При отказе сохранить контекст и показать причину. При неясном ответе обновить серверное состояние. [Отмена](../../src/web/routers/admin/tickets.py#L1052) · [Удаление](../../src/web/routers/admin/tickets.py#L1084) · [Ограничения ролей](../../src/application/services/role_service.py#L86)

## J-016 — Настроить отображение очереди

Опция Could по FR-016. Admin с доступом к очереди выбирает видимые столбцы и сортировку для текущей области. При согласованной модели хранения приложение локально восстанавливает только безопасные предпочтения этого аккаунта и этой области после обновления страницы. «Сбросить настройки отображения» восстанавливает значения по умолчанию. Записи заявок, поисковый текст, фильтры с персональными данными, черновики и токены не входят в пресет. При недоступном хранилище очередь открывается со стандартным видом. Нового API нет. Приёмка AC-016 проверяет обновление страницы, независимость двух областей, сброс и смену аккаунта. [FR-016](FUNCTIONAL_REQUIREMENTS.md) · [DEC-013, DEC-017](DECISIONS.md)

## J-017 — Проверить границу релиза

FR-017 со статусом Won’t проверяет границу релиза и не описывает отдельную пользовательскую задачу. В Admin остаются разрешённые административные карточки пользователей клиентов. Приёмка AC-017 проверяет отсутствие отдельного входа User, клиентского подтверждения, вложений, массовых действий и прямого изменения определения роли. Трасса обычных сценариев Admin должна обходиться без вызовов `/user/tickets`. [FR-017](FUNCTIONAL_REQUIREMENTS.md) · [DEC-001, DEC-002, DEC-020](DECISIONS.md)
