# Совместимость frontend v2 и backend

Таблица привязывает проблемы исходного UI к решениям v3. Факты v2 относятся к `88e8bfb`. Рекомендации с Proposed в [DECISIONS.md](DECISIONS.md) ожидают согласования.

| В v2 | API и ограничение | Действие v3 | Трассировка |
|---|---|---|---|
| Login Admin, токены в localStorage | JSON refresh ротируется и сохраняет абсолютный срок | Восстановление действующей сессии, scoped storage по DEC-010 | FR-001, FR-002 |
| Безадресная навигация и один selected Ticket | У отдельной заявки есть GET по ID | URL и рабочие вкладки, возврат из связанных карточек | FR-004, FR-005, FR-006 |
| Modal закрывается от backdrop, не управляет фокусом | UI-ограничение | Диалог с явным выходом, верхний Escape, возврат фокуса | FR-005, NFR-006 |
| Общий поиск и фильтр статуса расходятся | Статусы lower snake case, произвольных query для Ticket нет | Нормализация статусов и подписей; поиск, сортировка, пагинация в пределах выбранной выдачи | FR-003 |
| Новые записи видны в конце, нет даты создания | Сервер сортирует список по ID, возвращает историю | Колонка из первого статуса, предлагаемый стабильный порядок новых сверху | FR-003, FR-004 |
| Выбор отдела из активных и отключённых | Backend защищает новую связь с отключённым отделом | Отображать архивную ссылку, предлагать активные значения для новой связи | FR-007 |
| Исполнитель из всех Admin | Сервер назначает действующего Admin совпадающего отдела | Scoped UI-подбор при `admin.view`; серверная проверка на сохранении | FR-009 |
| Длинные списки клиентов и User | Оба URL scoped User работают, GET /admin/users/?client_id=… и /client/{id} | Поисковый combobox, явный путь клиента, сброс связанных полей и устаревшего запроса | FR-006, FR-007 |
| Комментарии в дочернем диалоге | POST /comments поддерживает Idempotency-Key | Поле в карточке и безопасный повтор того же намерения | FR-008 |
| Признак удалённой рекомендации и обычный старт | Раздельные `remote_work_recommended` и `work_is_remote`, отдельный атомарный PATCH | Метка из DEC-003, одна команда и обновление актуального состояния | FR-010 |
| В потоке можно смешать ожидание Admin и User | `ready_for_review` Admin и `waiting_for_confirmation` User относятся к разным агрегатам | User за пределами релиза, отдельная Admin-очередь Proposed, административное завершение отдельно от сдачи результата | FR-009, FR-011, FR-017 |
| Роли привязаны к сохранению профиля, каталог может не загрузиться | POST/DELETE с `roles` возвращают профиль, отсутствие общей транзакции и update роли | Отдельное действие, минимальные дельты, состояние частичного результата, явный повтор чтения | FR-013 |
| Одинаковое отображение сбоя и пустого набора | Есть отдельные статусы ошибок и 204 | Разные состояния и безопасные действия восстановления | FR-014 |
| Устаревший кэш и запись со старого снимка | Публичные мутации без условного revision, 409 только в серверной транзакции | Кэш по сессии, pre-read сравнение изменённых полей и сохранение черновика | FR-007, FR-014 |
| Доступность удаления зависит от UI | Отдельные права и серверные ограничения, физическое удаление Ticket каскадно | Ясная причина и область последствий, явное подтверждение, перечитать после неизвестного исхода | FR-015 |
