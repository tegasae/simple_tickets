# План повторного использования frontend v2

Предложение по `frontend_new@5e2a8e6`. Исходный инвентарь включает все 34 отслеживаемых авторских файла под `simple_tickets_frontend_v2/` и 371 запись под `node_modules/`. Исходные пути в таблицах указаны относительно `simple_tickets_frontend_v2/`, целевые — относительно `simple_tickets_frontend_v3/`. Целевые файлы проектные. Они создаются после разрешения перейти к реализации.

Категории применяются к целым файлам или явно выделенным функциям. Для целого авторского файла безусловный перенос без изменений пока не предлагается. Чистые функции можно перенести без изменений после проверки контрактов. Общее направление определяют DEC-011–DEC-017 и [ARCHITECTURE.md](ARCHITECTURE.md).

## 5. Порядок первой вертикали

1. После разрешения на реализацию подготовить манифест, проверенный lockfile, HTML, dev proxy и точку входа.
2. Выборочно адаптировать форму входа и оболочку, транспорт и права. Проверить требование восстановления и согласованную модель хранения.
3. Использовать небольшую часть таблицы и утилит статуса и даты для чтения очереди и карточки. Проверить прямую ссылку и возврат.
4. Подтвердить сборку, тесты клиентских состояний и чтение из изолированного backend. Последующие карточки, мутации, вкладки и справочники перенести отдельными вертикалями.
