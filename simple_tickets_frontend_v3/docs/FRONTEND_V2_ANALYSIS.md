# Анализ frontend v2

Статический анализ `simple_tickets_frontend_v2/` в `frontend_new@5e2a8e6`. Исходное дерево v2 в этой версии совпадает с деревом первоначального исследования на `88e8bfb`. Код, приложение, тесты и сборка v2 на проектном этапе не запускались. [Первоначальный отчёт](INITIAL_RESEARCH_REPORT.md) · [План повторного использования](CODE_REUSE_PLAN.md)

## 1. Технологии и поставка

V2 — SPA на JavaScript/JSX, ESM, React и React DOM `19.2.8`, Vite `8.1.5` и `@vitejs/plugin-react` `6.0.4`. npm использует lockfile версии 3. Проект объявляет `dev`, `build` и `preview`. Версии Node/npm в манифесте не закреплены. Пересечение требований к Node определяется всем графом lockfile. Прикладные frontend-тесты, команды линтинга и форматирования в манифесте отсутствуют. Маршрутизация, состояние, формы, таблицы и HTTP реализованы React и браузерными API. Дополнительно в Git отслеживается 371 файл под `node_modules/`. [Манифест](../../simple_tickets_frontend_v2/package.json) · [Lockfile](../../simple_tickets_frontend_v2/package-lock.json)

`index.html` загружает `src/main.jsx`. Точка входа монтирует `App` в `StrictMode` и подключает `base.css` и `themes.css`. `App` удерживает сессию, разрешения, уведомление, тему, `activePage` и контекст перехода. `Shell` фильтрует пункты по разрешениям. Компонент каждой страницы дополнительно проверяет чтение и отдельные действия. URL разделов, предсказуемая браузерная история и постоянство открытой карточки отсутствуют. Тема хранится отдельно и применяется через `data-theme`. [main.jsx](../../simple_tickets_frontend_v2/src/main.jsx#L1) · [App.jsx](../../simple_tickets_frontend_v2/src/App.jsx#L23) · [Shell.jsx](../../simple_tickets_frontend_v2/src/components/Shell.jsx#L13)

## 3. Транспорт, данные и состояние

- `api.js` централизует `fetch`, Bearer, один общий refresh после 401 и повтор запроса после успешной ротации. Login отправляет form-url-encoded, остальные операции с телом используют JSON. 204 уже выделен отдельно. `VITE_API_PREFIX` по умолчанию `/api`. Dev proxy удаляет префикс и переадресует к `BACKEND_BASE_URL` или `127.0.0.1:8000`. Сборке нужен внешний маршрут к API. [api.js](../../simple_tickets_frontend_v2/src/api.js#L9) · [vite.config.js](../../simple_tickets_frontend_v2/vite.config.js#L4)
- `storage.js` хранит access, refresh, логин, тему и локальные настройки в `localStorage`. В транспорте есть единый выполняющийся refresh, а защиты поколения сессии и отмены GET нет. Структурированная ошибка 422 сворачивается в строку из сообщений. `buildUrl()` пропускает абсолютный адрес, а `request()` добавляет Bearer. Текущие вызовы используют константные относительные маршруты. Для v3 эту гарантию стоит закрепить на уровне транспорта. [storage.js](../../simple_tickets_frontend_v2/src/storage.js#L1) · [api.js](../../simple_tickets_frontend_v2/src/api.js#L38) · [api.js, refresh и request](../../simple_tickets_frontend_v2/src/api.js#L73)
- `ReferenceDataProvider` хранит клиентов, сотрудников, отделы и пользователей в памяти. Он лениво подгружает списки и отдельные записи, индексирует User по ID и клиенту, дедуплицирует одинаковые запросы, подменяет или удаляет строки после изменений. Дедупликация не объединяет обычный и принудительный запросы. Поздняя загрузка может заменить более новые данные. Несколько справочников распространяются через один Context. [referenceData.jsx](../../simple_tickets_frontend_v2/src/referenceData.jsx#L21) · [Загрузка коллекций](../../simple_tickets_frontend_v2/src/referenceData.jsx#L106) · [Пользователи по клиенту](../../simple_tickets_frontend_v2/src/referenceData.jsx#L193)
- `TicketsPage` получает массивы заявок с историей и выполняет фильтрацию в браузере. `DataTable` дополнительно фильтрует по колонкам, сортирует и только затем делит на страницы. Пересекающиеся запросы разных видов не упорядочены. После мутации текущий список заменяет строку по ID, не пересчитывая, подходит ли она всё ещё под серверный вид. Это важно, например, при закрытии открытой заявки. [TicketsPage.jsx](../../simple_tickets_frontend_v2/src/components/TicketsPage.jsx#L112) · [Обновление после записи](../../simple_tickets_frontend_v2/src/components/TicketsPage.jsx#L244) · [DataTable.jsx](../../simple_tickets_frontend_v2/src/components/DataTable.jsx#L36)
- Формы контролируются React. Используются HTML-атрибуты, ручные проверки, преобразование ID и дат. Результаты читаются как JS-объекты. Справочники, статусы и рабочие операции не стоит переносить копированием документации v2. Источник текущего контракта — backend и подтверждённый [API_CONTRACT.md](API_CONTRACT.md). [Форма заявки](../../simple_tickets_frontend_v2/src/components/TicketsPage.jsx#L266) · [Утилиты дат](../../simple_tickets_frontend_v2/src/ticketUtils.js#L76)

## 5. Что сохранить в проекте

Подход v2 к централизованному REST-клиенту, простым формам и локальной обработке разрешённой выборки годится как основа. Чистые преобразования, историю, комментарии, оболочку и стили переносить выборочно. Обновление серверного состояния, URL-навигация, модальность, точные разрешения и сессия требуют изменений. Выбор по каждому авторскому файлу, риски и необходимые проверки собраны в [CODE_REUSE_PLAN.md](CODE_REUSE_PLAN.md).
