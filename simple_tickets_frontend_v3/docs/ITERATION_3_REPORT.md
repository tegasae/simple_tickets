# Отчёт о реализации I3

**I3 · DONE.** В ветке `frontend_new` выполнены BK-005 и BK-006 для рабочего места Admin. Владелец дал команду начать реализацию и ранее задал подпись «Взято в работу на горячей линии». [Решения](DECISIONS.md) · [План](IMPLEMENTATION_PLAN.md#i3-обработка-заявки).

| Требование | Реализация |
|---|---|
| FR-009. Приёмка и работа | В карточке доступны приёмка, отклонение с причиной, отложить с причиной и назначение действующего сотрудника отдела. Исполнитель может начать, приостановить, продолжить и сдать работу. Ретроспективная форма принимает интервал или длительность. Сдача даёт `READY_FOR_REVIEW`. Завершение проверки требует `ticket.executed` и переводит заявку в `EXECUTED`. |
| FR-010. Горячая линия | В списке и карточке показана метка «Рекомендовано для горячей линии». Очередь выводится из открытых заявок для роли горячей линии. В карточке один `PATCH /admin/tickets/{id}/start-remote-work` с `{}` запускает удалённый `AT_WORK`. Для `ACCEPTED` сервер в той же операции назначает текущего Admin. |

Политика действий учитывает текущее разрешение, состояние, исполнителя и режим эпизода. Список кандидатов для назначения требует `admin.view`. Для принятой заявки горячей линии действующий отдел текущего Admin проверяет сервер, поскольку минимальная роль может работать без доступа к профилям. Отказ объясняет условия сверки. Подписи, ошибки и доступные имена действий используют ключи интерфейсного словаря. [Политика](../src/features/tickets/workflow/policy.js) · [Панель](../src/features/tickets/workflow/WorkflowPanel.jsx) · [Контракт API](API_CONTRACT.md).

## Сверка переходов

- Перед записью отдельный GET сверяет состояние, исполнителя, отдел, рекомендацию и историю с карточкой. При видимом расхождении PATCH пропускается, форма остаётся во вкладке. Между чтением и PATCH остаётся возможность гонки. Правила перехода и согласованность записи проверяет backend.
- Прямой ответ подтверждает команду по новым ID истории, актёру и параметрам. Для старта из `ACCEPTED` и регистрации задним числом сверяются обе записи с одним временем регистрации.
- При потерянном ответе повтор заблокирован. «Проверить состояние» перечитывает заявку, сохраняет ввод и сверяет новые записи. Неизменившаяся или расходящаяся история оставляет действие неопределённым. Подтверждённое закрытие вкладки удаляет локальные данные сверки. [Рабочая область](../src/features/tickets/useTicketWork.js) · [Сверка истории](../src/features/tickets/workflow/receipts.js).
