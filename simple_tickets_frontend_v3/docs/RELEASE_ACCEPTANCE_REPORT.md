## Стенд и сборка

- Чистый `npm ci` из закоммиченного lockfile. Node 24.22.3, npm 11.19.1, React 19.2.8 и Vite 8.1.5. Две production-сборки после исправлений совпали по именам и SHA-256 всех шести файлов. [Порядок сборки](../README.md#проверки-и-сборка).
- Python 3.14.10 использовал точные версии `requirements.txt`, в том числе FastAPI 0.143.0, Starlette 1.8.0, Pydantic 2.14.1 и Uvicorn 0.54.0, с SQLite 3.53.1. Штатные тесты запущены с pytest 9.2.0. [Зависимости](../../requirements.txt) · [Изолированная фикстура](../tests/backend_contract.py).
- Nginx 1.26.3 обслуживал один origin с отдельными `/api/`, `/config/`, `/assets/` и SPA. TLS проверен с доверием к временному сертификату. Через HTTPS проверены глубокая ссылка, MIME и кэширование, `401/404`, вход, права, чтение заявки, ротация и отзыв refresh. На финальном ассете Chromium повторил вход и восстановление по прямой ссылке в защищённом контексте. [Схема размещения](RUNTIME_CONFIGURATION.md#размещение).

## Производительность и доступность

Отдельные замеры использовали 100 и 5000 синтетических открытых заявок, по 20 наблюдений после трёх прогревов на метрику. Chromium запускался в headless при 1440×900, ответы были заранее сериализованы. DOM очереди содержал 25 строк, локальный поиск выполнил 0 запросов к API заявок, смена рабочей вкладки — один GET карточки. [Воспроизводимый браузерный замер](../tests/browser_performance.py).

| Замер Chromium, p50 / p95 | 100 заявок | 5000 заявок |
|---|---:|---:|
| Повторное чтение очереди до обновления DOM | 20,0 / 26,2 мс | 126,5 / 170,4 мс |
| Передача JSON очереди по loopback | 2,7 / 5,1 мс | 36,0 / 44,7 мс |
| Размер синтетического JSON | 197 780 байт | 9 966 600 байт |
| Локальный поиск до обновления DOM | 3,8 / 8,1 мс | 61,7 / 81,8 мс |
| Переключение рабочей вкладки до обновления DOM | 11,1 / 19,7 мс | 8,8 / 30,9 мс |

В реальном FastAPI с SQLite замерено время до получения ответа через TestClient, включая чтение БД и сериализацию. Эти замеры выполнены отдельно от браузера, сетевой передачи и конкурентной нагрузки.

Независимая проверка доступности использовала Chromium при фактическом масштабе 200%, включая ширину 320 CSS px. Подтверждены видимый клавиатурный фокус, локальная прокрутка таблицы, доступные имена в дереве AX, возврат к фильтрованному списку, диалог закрытия, назначение и горячая линия. ## Дополнительные проверки на локальном стенде

27 ноября 2026 года повторно собран кандидат `1fbf6ad`. SHA-256 JS и CSS совпали с таблицей выше. Nginx 1.26.3 обслуживал эту сборку по HTTPS на loopback с отдельным каталогом `/config/`. Проверены цепочка TLS с временным CA, прямая ссылка на карточку, MIME и кэширование, отсутствие SPA fallback для пропущенных файлов и API, ответы `/api/health` 200 и защищённого API 401.

- Штатная миграция выполнена дважды на отдельной копии тестовой `db/admins.db`. Обе проверки `integrity_check` и `foreign_key_check` прошли. [Миграция](../../scripts/migrate_backend_storage.py).
- Локальная сборка образа FastAPI использовала базовый `python:3.14-slim` и закреплённые зависимости. Сетевой `pip install` внутри сборки завершился ошибкой проверки сертификата облачного прокси. Для повтора зависимости скачаны с проверкой TLS и установлены офлайн из временного набора wheel-файлов. Контейнер без внешней сети запустил Uvicorn с тестовой копией SQLite. Проверены схема, `/health` 200 и защищённый маршрут 401. [Dockerfile backend](../../dockerfiles/backend/Dockerfile).
- Повторный прогон дал 65/65 Node, 35/35 штатных backend-тестов и 24/24 проверок контракта. В Chromium 156 прошли 33/33 сценария через локальные Nginx и реальный FastAPI и 2/2 сценария замены темы и текстов в отдельной копии сборки. Браузер доверял закреплённому открытому ключу временного сертификата. Синтетические роли покрыли разрешённые действия и отказы при входе, создании, редактировании, назначении, работе горячей линии, проверке, отмене и удалении заявок, а также управлении аккаунтами и ролями. [Браузерные тесты](../tests/) · [Контракт](../tests/backend_contract.py).
- В Firefox ESR 153.8.0 и WebKitGTK 2.54.3 прошли вход синтетического читателя, прямая ссылка, навигация очередь → карточка → назад, возврат фокуса, 404, выбор темы и применение опубликованного JSON языка. Проверки использовали изолированные ответы API. Firefox управлялся через BiDi. Для WebKit использован нативный GTK WebView после таймаута открытия WebDriver-сессии MiniBrowser.
- Orca 48.1 с Chromium 156 передал синтезатору заголовок страницы, имена полей логина и пароля, признак обязательного ввода, кнопки показа пароля и входа, ошибку 401, поиск и заголовки очереди и открытой карточки. Проверка использовала синтетические ответы API и журнал синтеза речи через Speech Dispatcher.
- Orca не произнёс «Подходящих заявок не найдено». В Chromium существующий `role="status"` остался в дереве доступности с `live=polite` и `atomic=true`. Текст обновился в том же узле, фокус остался в поле поиска, AT-SPI получил событие изменения текста. Два дополнительных прогона с явным `aria-live="polite"` и с открытым для просмотра статусом дали тот же результат. Причина сбоя речевого объявления A11Y-09 остаётся открытой. [Критерии доступности](ACCESSIBILITY.md#проверяемые-требования).

## Условия эксплуатационного допуска

- На целевом стенде проверить публикацию и откат сборки, TLS, внешний `/config/`, маршруты SPA/API и журналирование без чувствительных данных. При обновлении backend проверить образ и миграцию тестовой копии целевой БД. Повторить ключевые сценарии с фактическими наборами прав диспетчера, исполнителя, горячей линии и администратора.
- Для отдельной статической публикации v3 проверена схема размещения Nginx. Штатный Dockerfile frontend собирает v2. Способ поставки v3 на целевой хост ещё требуется выбрать. [Схема v3](RUNTIME_CONFIGURATION.md#размещение) · [Dockerfile frontend](../../dockerfiles/frontend/Dockerfile).
- Согласовать браузеры и проверить их на целевых рабочих местах. В проверку WCAG 2.2 AA включить объявление результатов поиска экранным считывателем по A11Y-09. Для пользовательской приёмки нужны представители ролей Admin.
- Согласовать обычный и пиковый объём очереди, частоту запросов и устройство. На синтетических 5000 заявок задержка API и размер полной выборки заметно растут. Производственный порог зависит от фактической нагрузки. [Нефункциональные требования](NON_FUNCTIONAL_REQUIREMENTS.md) · [Риски](RISKS.md).
