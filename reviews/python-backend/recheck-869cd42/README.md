# Приёмка Python-бэкенда после четвёртой проверки

Проверена ветка `api-new-client-scheme` репозитория `tegasae/simple_tickets`, коммит **869cd424b1b9f13babd720884a3cbb7e0f6a10bb**. В прежнем перечне 4 исправления подтверждены в проверенной SQLite, 4 пункта остаются открытыми, у одного уточнено требование. Четыре дополнительно выявленных дефекта воспроизвелись и на 5288dea. Для N01, N06, нормализации версий и четырёх дефектов подготовлена серия из шести unified diff. В первом прогоне серии во временной копии прошли 195 приёмочных тестов и 70 исторических регрессий. Два приёмочных теста прежнего формата refresh пропущены. [Входной снимок](input-state.md) · [Сравнение](previous-findings.md) · [Фактические запуски](tests/results.md)

В сквозных сценариях User создал связанную пару. Admin принял заявку, назначил отдел и исполнителя, провёл очную или удалённую работу и передал результат на проверку. User подтвердил выполнение. Повторное чтение обеих карточек вернуло `CONFIRMED_BY_USER`. Попытка раннего подтверждения вернула 400 без изменений пары. При назначении чужого отдела и при конфликте версий обе карточки сохранили прежние статусы и историю. Согласованные начальные изменения контакта работают с обеих сторон. Отключение только контакта закрывает уже готовую к проверке пару в SUSPENDED. [Приёмка назначения](tests/results.md#f-04) · [Сквозные сценарии](tests/results.md#сквозные-сценарии) · [Контакт](tests/results.md#контроль-контакта)

## Редакция репозиториев по уточнению владельца

Комплект воспроизводит все 62 пути, опубликованные в `2868a64cb58041fc3aea3852ecf7c36297562b9d`. Исполняемый код патчей 05–10 проверяется на исходном снимке `869cd424b1b9f13babd720884a3cbb7e0f6a10bb`.

В 05 и 06 использованы доменные контракты `ABC` с `@abstractmethod` и SQLite-реализации, наследующие `BaseRepository`. SQL находится в Gateway, отображение между объектами, параметрами и строками БД находится в Mapper. Репозитории используют соединение текущего `SQLiteUnitOfWork`. Для `create_response` уточнена параметризация возвращаемой модели. [Архитектура и применимость](patches/README.md#редакция-репозиториев) · [Повторные проверки](tests/results.md#проверка-редакции-репозиториев)

В новом комплекте прошли **196 приёмочных и 70 исторических проверок**. OpenAPI совпал целиком.

Исходные независимые заключения относятся к своим историческим версиям. Пересмотр реализации и выводы консилиума по этой редакции приведены в дополнениях к запискам авторов и итоговому арбитражу. Очищенный дамп `db/dump_migration.sql` входит в комплект как точная копия опубликованного файла со схемой 05–06.

## Порядок применения

1. **05**. Схема, постоянно хранимый отзыв и согласование версий. При запуске новой версии прежние refresh прекращают действовать и нужен повторный вход. Существующая БД обновляется в окно с остановленными writers. Поддерживаемый исходный DDL и отказ при несовместимой схеме проверены синтетически.
2. **06**. Ключи десяти созданий и совместный COMMIT. Скрипт перехода из 05 включит таблицу результатов. Клиент решает, когда повторять. Для заголовка выбраны видимые ASCII-символы без пробелов, максимум 128. Смена серверного ключа HMAC в течение окна вызывает 409 на старый повтор. Дубль при этом не создаётся.
3. **07–10**. Небольшие поправки для начального состояния отдела, пропуска назначения, нормализации логина и семантики истории. Они применены после двух основных патчей в общей проверке. Патч 01 предыдущего прохода исключён по согласованному правилу авторства.

## Охват и ограничения

Выполнены анализ Python и SQLite схемы, 167 проверок AST исходника и 173 плюс скрипт миграции в серии, три импорта, создание приложения, чтение `/health` и OpenAPI, подготовка 115 исходных SQL запросов, FK и integrity check. FastAPI проверялся через TestClient. SQLite использовала отдельные временные файлы и синтетические записи. [Протокол и команды](tests/README.md) · [Данные smoke](tests/smoke-results.json)

Порядки конкурентной фиксации на будущем PostgreSQL, работа Python 3.14 в контейнере и фактическая production-схема остаются за пределами подтверждения. Нормальная SQLite-занятость может вернуть 503 до сравнения версии. Новый HTTP-запрос с новым UoW после снятия блокировки проверен. Повтор операции на прежнем мутированном Python-объекте после rollback не гарантирован. Реальные базы, содержимое .env, клиентский код и архивы исключены из охвата. [Границы Python](experts/round-03/python.md) · [Реестр приёмки](features.md)

По принятым правилам рабочих сценариев вопросов для владельца не осталось. Перед production-переходом нужны фактическая версия схемы и окно обновления workers. Политику отдельной ротации ключа отпечатков следует определить, если смена signing key без паузы в 24 часа станет штатной операцией. Проверку связанных PostgreSQL-операций проводят после появления соответствующего адаптера. [Принятые правила и технические решения](docs/requirements.md)
