# Итог независимого арбитража

Принимаю серию 05–10 для штатного FastAPI и синтетической SQLite по перечисленным ниже критериям. На исходном 869cd42 сохраняются N01, N06 и четыре прикладных отклонения. В первичном заключении я опирался на статическую трассировку workflow. В финальном протоколе есть исполнения от входа по ролям до повторной загрузки пары и её историй. Утверждения о сроках подтверждены обоими способами.

Сопоставлены три раунда А, Б и В, материалы реализации, документы владельца, исходный реестр прошлой проверки на 5288dea и результаты принятой серии. ## Разрешение расхождений и приоритеты

1. В первую очередь принять 05 вместе с миграцией. Старый access после смены пароля может работать до exp у активного субъекта, прежний refresh постоянно выведен из обращения. Отключение субъекта может прервать доступ раньше. Проверка каждого access через sid не требуется. Сессии отдельно живущих старых процессов нельзя считать переведёнными одним лишь исполнением миграции. Требуется фактическое переключение всех процессов.
2. Затем принять 06. Конфликт с эквивалентным входом был бы дефектом нормализации. В текущей версии Value Objects, множества прав и ролей и значения по умолчанию участвуют в канонизации. Сохранённый ответ возвращается после проверки разрешения. Остановка между COMMIT и записью срока оставляет ответ доступным. Последующее успешное обращение может начать полное окно позднее. Вложенный Account входит в результат команды сотрудника при переданных учётных данных.
3. Принять 07–10 отдельными исправлениями к прежнему поведению. Они не являются четырьмя регрессиями, внесёнными diff от 5288dea. На прежнем снимке воспроизведены семь падений контрольной выборки D01–D04.
4. Сохранить внешнее CREATED от User, внутреннюю регистрацию от Admin и фактического автора ordinary comment. Исторический 01 отклонён. По уточнению владельца контакт можно менять в обеих начальных открытых карточках и в ACCEPTED/DEFERRED. Отключение отдельного контакта в READY также закрывает пару. Отключение владельца и клиента закрывает READY, активная работа продолжается до finish и отдельной команды Admin execute. Для будущего 1:N уникальность связи не требуется. [Контакт](../tests/test_contact_policy.py) · [Авторство](../tests/test_comment_api.py) · [Сквозной процесс](../tests/test_full_workflow.py)
5. Для решения о production отдельно нужны фактический PostgreSQL-адаптер, миграция на поддерживаемой версии целевой СУБД и синхронизированные два соединения для назначения, отзыва и повтора. Нынешние результаты не устанавливают поведение PostgreSQL, фактической базы или выкладки Python 3.14. Повторные отказные тесты намеренно ограничены штатными синтетическими входами.
