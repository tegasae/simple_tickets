# Реализация патчей 07 и 08

Основание — снимок `869cd424b1b9f13babd720884a3cbb7e0f6a10bb` после 05 и 06 в выданном `verified-series`. Владелец подтвердил начальное состояние Department из запроса и различие между пропуском поля и явным 0 в обновлении Admin.

- `POST /admin/departments/` передаёт `DepartmentDTO.enabled` в доменную фабрику через прикладной сервис. И HTTP-модель, и DTO уже задают `true` по умолчанию. HTTP-модель отвергает явный `null` с 422. Ответ для `false`, последующий GET и запись в SQLite согласованы. [07-department-initial-state.patch](../patches/07-department-initial-state.patch)
- В `PUT /admin/admins/{id}` признак присутствия `department_id` берётся из `model_fields_set`. При пропуске прикладной сервис передаёт в операцию обновления профиля `department=None`, доменный сервис использует текущий ID. Поле в OpenAPI остаётся необязательным целым числом, пояснение описывает пропуск и 0. При явном 0 используется существующая операция снятия отдела с проверкой текущих назначений. Для положительного ID сохранены загрузка, `touch`, проверка активного отдела и проверка назначений при смене. Явный `null` отклоняет HTTP-модель. Прежний вызов `update_admin(admin_dto=...)` сохраняет семантику снятия отдела при значении DTO по умолчанию 0. [08-preserve-admin-department.patch](../patches/08-preserve-admin-department.patch)

## Проверка

На исходной серии 05/06 из 24 проверок 21 прошла, три воспроизвели разночтения. API сохранял `enabled:false` как `true`, а пропуск `department_id` снимал отдел у свободного сотрудника или давал 400 при текущем назначении.

Вторая чистая копия серии приняла оба патча последовательно через `git apply --check` и `git apply`. На ней прошли все 24 предоставленные проверки `test_department_initial_state.py`, `test_admin_profile_department.py` и `test_executor_guard.py`. Три дополнительные проверки, выполненные только во временной копии, подтвердили прежнее значение по умолчанию у прямого прикладного вызова, отказ при переводе в отключённый отдел и повтор создания Department по ключу N06. Повтор вернул прежний объект с `enabled:false`, смена входа под тем же ключом получила 409.

Итого 27 прошедших проверок через Python 3.12.14 на синтетических SQLite. `git diff --check` прошёл. Pytest вывел существующие предупреждения об устаревших интерфейсах TestClient, Pydantic и адаптере datetime SQLite.


## Независимая сверка границ слоёв

Аналитик проверил обе реализации по образцам проекта. Доменный контракт задаёт операции, репозиторий использует соединение общей UoW, SQL и преобразование данных находятся в Gateway и Mapper. Существующие прикладные сервисы сохраняют бизнес-проверки. HTTP-ключ и сериализация исходного ответа остаются в веб-слое. Координатор отдельно сравнил OpenAPI целиком.

Аналитик проверил на отдельной синтетической SQLite запись сессии, точную границу истечения, откат отзыва и удаление сессии при удалении Account. Для 06 он проверил дубликат зарезервированного ключа и временный отказ общего репозитория после бизнес-COMMIT. Первая команда вернула 201, повтор вернул тот же ответ, а отметка срока была восстановлена. [Результаты](../tests/results.md#проверка-редакции-репозиториев)
