## Редакция репозиториев

| Слой | Refresh в 05 | Результаты создания в 06 |
|---|---|---|
| Доменный контракт | `RefreshSessionRepository(ABC)` | `CreationResultRepository(ABC)` |
| Адаптер | `RefreshSessionRepositorySQLite(BaseRepository, RefreshSessionRepository)` | `CreationResultRepositorySQLite(BaseRepository, CreationResultRepository)` |
| SQL | `RefreshSessionGateway` | `CreationResultGateway` |
| Строки и параметры | `RefreshSessionMapper`, даты UTC и JSON области | `CreationResultMapper`, ключ, отпечаток, статус, JSON и срок |

Точка сборки SQLite — `SQLiteUnitOfWork`. Оба репозитория получают его `Connection`. Ошибки SQL переводятся общей логикой `BaseRepository`. При резервировании ключа конфликт уникальности превращается в `CreationAlreadyReserved`. На уровне команды после отката выполняется чтение готового результата. Ошибка обслуживания TTL после основного COMMIT сохраняет доступность результата и возможность повторной отметки срока.

Для другой реляционной СУБД используются те же доменные контракты и операции. В новом адаптере потребуется подключить драйвер, его параметры запросов и отображение ошибок, использовать представление времени и JSON целевой БД, установить схему и реализовать Unit of Work. Приёмка на целевом драйвере должна подтвердить общую транзакцию, конфликт составного ключа, откат и конкуренцию выдачи сессий с отзывом. SQLite-реализация хранит SQL в Gateway и сборку соединения в UoW. [Повторные проверки](../tests/results.md#проверка-редакции-репозиториев)
