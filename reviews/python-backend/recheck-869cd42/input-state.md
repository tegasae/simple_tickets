Команды установления входа

```bash
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
git status --short --branch --untracked-files=all
git diff --binary HEAD | sha256sum
git diff --cached --binary HEAD | sha256sum
git diff --name-status 5288dea..869cd42
```

Отпечаток локальных изменений: SHA-256 по байтам `git diff --binary HEAD`, отдельно для индексированного diff. Для каждого пути из NUL-формата `git status --porcelain=v1 -z --untracked-files=all` записаны XY и SHA-256 байтов файла. Вывод полного списка есть в JSON. Включённые в аудит Git-файлы распакованы под `/tmp` через архив полного SHA. Старые добавленные материалы не перекрывают целевую версию исходников. Наполнение и версии текущих локальных материалов сверяются повторно при финальном Git контроле.

Общий вход экспертов содержит 202 файла. Их SHA-256 записаны по отсортированным относительным путям. Из них 201 файл из коммита и одно одинаковое уточнение [OWNER-SCOPE.md](docs/owner-scope.md). SHA-256 JSON-манифеста `82cc83f77e18aae407893e96071e82da07b76a76e942636bd0f1c5e4698b1b41`. [Манифест](input-manifest.json)

Охват включает src, Python утилиты, DDL, конфигурацию запуска и тестирования, Dockerfile бэкенда, документацию и заметки. Корневой `readme.md` прочитан полностью. Его TODO содержит прежний план «только Admin», хотя текущий `POST /user/tickets/` работает. Источник требований и уточнений указан отдельно. Старые заключения не передавались экспертам до сдачи слепых отчётов. [Требования](docs/requirements.md)

Фронтенд, архивы, рабочие БД и .env исключены из копий и результатов. В них также отсутствуют секреты, выводы с реальными токенами и персональные данные. Для исполнения используются отдельные временные SQLite, случайные синтетические логины и ключи, `PYTHONDONTWRITEBYTECODE=1` и выключенный pytest cache. Основной файл приложения берёт путь из `DATABASE_URL`. Текущий refresh backend получает отдельную синтетическую настройку, гипотеза с бывшим хранилищем в основной БД проверена при миграции.
