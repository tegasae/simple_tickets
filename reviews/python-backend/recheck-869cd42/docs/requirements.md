## Комментарии и авторство

Поля `comments[].comment` и `statuses[].comment` в Admin API возвращают текст, а пустое поле истории возвращается как `""`. Обычный комментарий принадлежит тому, кто ввёл его.

Внешний `TicketUser.CREATED` обозначает подачу заявки. При звонке автором события остаётся User. Регистратор Admin сохраняется во внутреннем `CREATED_FROM_REQUEST_USER`. Прежняя строка об авторе CREATED в §2 полного документа уточнена владельцем после аудита. N04 снят, старый патч `01-created-actor.patch` исключён.

## Сроки и отзыв сессий

Сроки по умолчанию составляют 5 минут для access и 7 суток от исходного входа для refresh. Ротация сохраняет абсолютный дедлайн, включая предел нового access. Подпись, срок access и действующие проверки активности и прав продолжают применяться. Access, выданный раньше, живёт до своего `exp`, пока проходят проверки доступа.

Смена пароля, замена реквизитов существующего Account, отключение Account или сотрудника, удаление Account или сотрудника прекращают действие старых refresh. Включение не восстанавливает их. Каскад Client входит в общую транзакцию. Account и сессии хранятся в одной БД и используют одну UoW. Выдача и ротация согласуются с отзывом.

Для перехода владелец утвердил единое хранилище основной БД для всех запусков FastAPI, завершение старых сессий и повторный вход. Источник первоначальной даты прежних ротаций может быть утрачен, поэтому старый файл не переносится в новое хранилище. [Полный документ, §5](https://github.com/tegasae/simple_tickets/blob/869cd424b1b9f13babd720884a3cbb7e0f6a10bb/reviews/python-backend/recheck-5288dea/decisions-full.md#5-токены-и-отзыв-сессий) · [Ответы владельца, пункты 1 и 4](https://github.com/tegasae/simple_tickets/blob/869cd424b1b9f13babd720884a3cbb7e0f6a10bb/reviews/answers.md#L1-L3)

При обновлении SQLite прежние NULL в `employees.version`, `departments.version` и `clients.version` переходят в 0. Уже числовые версии сохраняются. ## Идемпотентность созданий

Для десяти POST из F-08 ключ необязателен. При переданном ключе область включает тип и ID авторизованного субъекта и команду. Цель комментария и нормализованное тело входят в отпечаток. Вложенный Account входит в создание Admin/User. Команды attach Account продолжают работать самостоятельно. Сохранённый успешный статус и тело повторяются при том же ключе, той же команде и совпавшем отпечатке после текущей проверки прав. Другое тело получает 409. После отката ключ свободен. Одна транзакция фиксирует ключ, подготовленный ответ и бизнес-записи вместе с историей. [Полный документ, §6–9](https://github.com/tegasae/simple_tickets/blob/869cd424b1b9f13babd720884a3cbb7e0f6a10bb/reviews/python-backend/recheck-5288dea/decisions-full.md#6-идемпотентность-область-и-сроки)

Владелец подтвердил штатную реакцию на занятость БД без выделенного таймера или нового Retry-After. Следующий HTTP-запрос делает клиент. Успех доступен 24 часа после фиксации. В обычном ходе отметка срока записывается сразу после COMMIT. Если процесс успел зафиксировать результат и завершился до отметки, результат остаётся пригодным для повтора, а срок назначается при следующем успешном сохранении с ключом или совпавшем replay без отметки. Владелец принял возможное увеличение срока в этом случае для защиты от дублей.

Выбор реализации заголовка задаёт ограничение в 128 видимых ASCII-символов без пробелов и один экземпляр заголовка. Для отпечатка используется HMAC с отдельной областью применения действующего ключа сервера. Ключ сервера должен совпадать у workers одной установки. Смена этого ключа в течение окна делает прежние отпечатки несопоставимыми, в результате повтор с прежним ключом получит конфликт. Исходное тело запроса не сохраняется.

## Создание Department и проверка логина

Во время согласования владелец подтвердил `enabled: false` как допустимое начальное состояние Department. При отсутствии поля ожидается `true`. Поле и значение по умолчанию заданы в модели запроса. Явный `null` отклоняется. [DepartmentCreateRequest](https://github.com/tegasae/simple_tickets/blob/869cd424b1b9f13babd720884a3cbb7e0f6a10bb/src/web/models/department.py#L10-L21)

Логин хранится с удалёнными пробелами и прочими пробельными символами по краям. Существующий формат ошибки при занятом каноническом логине — 400. Проверка должна применять ту же нормализацию до сохранения Account. ## Изменение профиля Admin

Владелец подтвердил, что отсутствие `department_id` в `PUT /admin/admins/{id}` сохраняет текущий отдел. Явный `0` запрашивает снятие назначения с обычной проверкой текущих заявок. Положительный ID сохраняет прежнюю процедуру смены отдела. Поле `null` отклоняется HTTP-валидацией. [Описание маршрута](https://github.com/tegasae/simple_tickets/blob/869cd424b1b9f13babd720884a3cbb7e0f6a10bb/src/web/routers/admin/admins.py#L153-L174)

## Контакт и готовая к проверке пара

В начальных открытых статусах сохраняется существующее разрешение изменить контакт. Это дополняет ранее подтверждённые ACCEPTED/DEFERRED. При отключении только контактного User связанная пара в READY_FOR_REVIEW закрывается как SUSPENDED даже при активном владельце. Два правила подтверждены владельцем после первого раунда.

## Режим работы в истории

Статус без режима использует `work_is_remote: null`, работа в офисе использует `false`, удалённая работа использует `true`. Значение, записанное доменом, сохраняется при повторном чтении. У старого рабочего статуса, требующего режима, SQL NULL продолжает читаться как прежний `false`, чтобы не ломать чтение старой истории.
