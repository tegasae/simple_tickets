# Действующие уточнения владельца для прохода 869cd42

- Телефонное обращение подаёт User. Внешний TicketUser.CREATED сохраняет User, внутреннюю регистрацию записывает Admin, ordinary comment имеет фактического автора. Исторический патч 01 не применять.
- Административный JSON comment — строка, как у User. Контакт у Ticket пользовательского происхождения положительный. Смена контакта разрешена на обеих карточках при ACCEPTED/DEFERRED. Нельзя включать Admin при отключённом назначенном Department или менять отдел при текущем назначении.
- Отключение владельца или клиента закрывает READY_FOR_REVIEW в SUSPENDED. AT_WORK продолжается. После finish работу отключённого клиента финализирует Admin отдельной командой. Модель будущего 1:N допускается. Текущий маршрут создаёт одну пару.
- Access 5 минут, refresh 7 суток от первого входа с неизменной абсолютной датой и ограничением exp. Не вводить обязательную отдельную sid-проверку каждого access. Смена пароля, удаление Account или сотрудника, отключение Account, сотрудника или Client постоянно отзывают refresh. Повторное включение не восстанавливает его. Выдача и ротация согласуются с отзывом, все штатные FastAPI процессы используют одну БД и UoW. При переводе завершить старые сессии, потребовать новый вход, не переносить их из отдельной БД или памяти.
- Версии Employee, Department, Client при изменении схемы: старые NULL преобразовать в 0, числовые сохранить, новые NOT NULL DEFAULT 0.
- Идемпотентность распространяется на команды создания Client, Department, Admin, User, обе Role, обе заявки и оба добавления обычного комментария. Account при создании Admin/User входит в родительскую команду. Ключ необязателен, запрос связывается с субъектом, командой и отпечатком нормализованного входа с целью команды. Успех хранится 24 часа и фиксируется вместе с записями и историей. Ответ на совпавший запрос возвращается после проверки доступа. Другой вход под сохранённым ключом даёт 409. Повтор делает клиент. Штатная обработка занятости остаётся без выделенного протокола ожидания. При остановке между COMMIT и отметкой срока сохранить результат, начать окно с последующего успешного обращения, даже если это продлевает хранение.
- Исходники, прежние материалы и рабочие данные доступны только для чтения. Запуски в независимых временных копиях с синтетической SQLite. Не читать .env, рабочие DB, архивы и фронтенд.
