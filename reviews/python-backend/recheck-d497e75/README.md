## Уточнённое правило владельца проекта

После завершения консилиума владелец проекта подтвердил, что отключение владельца или клиента закрывает заявки из `READY_FOR_REVIEW`. Внутренняя карточка переходит в `SUSPENDED`, связанная пользовательская — в финальный `SUSPENDED`. Дополнительная проверка качества выполнения после отключения не требуется. Патч 01 соответствует этому правилу для обоих каскадов. Сценарий отключения отдельного владельца дополнительно проверен через HTTP с повторным чтением обеих карточек и повтором команды.

## Что запускалось

Фикстуры создали SQLite из `db/schema.sql` и заполнили синтетическими данными. Временный пустой шаблон `db/admins.db` использовался только для тех штатных тестов, которые ищут файл по этому имени. Тесты авторизации использовали штатные собственные сессии. Авторизационные обходы оценивались статически.

- `ast.parse` для 164 Python-файлов, импорт `main`, `src.web.main`, `src.oauth2.main`. FastAPI `/health` и `/openapi.json` дали 200. Схема выполнилась и прошла `PRAGMA integrity_check`.
- `pytest ... old_review_tests` на текущем SHA дал **37 прошли, 2 упали**. Два старых теста также ожидали прежнюю политику для READY_FOR_REVIEW. Новые сценарии учитывают заметку автора. 
- `pytest ... --continue-on-collection-errors tests_pyramid` дал **46 прошли, 104 упали, 15 ошибок**. Причины включают отсутствующие импорты и устаревшие контракты. [Как воспроизвести](TESTING.md)

- После уточнения владельца проекта набор `recheck_tests` дал **1 прошёл, 20 упали** на текущем снимке и **21 прошла** после всех семи предложенных патчей. Проверка `git apply --check --whitespace=error-all` выполнена на временной копии снимка.
- В исправленной копии **37 прежних проверок прошли**, два старых сценария отключения исключены из этого прогона и заменены проверками нового правила. Штатная проверка SQL-констант из `tests_pyramid/contract/test_gateway_sql_contracts.py` дала **1 failed** на текущем SHA из-за отсутствующей колонки `admin_id` и **1 passed** в исправленной копии.
