## Основная регрессия

Одна параметризованная HTTP-регрессия на свежей DDL должна покрыть отключение клиента и сотрудника с парой в исходном, активном и ожидающем проверки состояниях. Для каждой строки проверить HTTP, флаги, точные статусы, число записей истории, `date_finished` и видимость в списках через отдельное соединение и свежий GET. Для продолжающейся работы проверить последующий `finish-work`, для закрытой пары проверить повтор отключения и отсутствие повторного открытия после включения. Для каскада сотрудника добавить раннюю пару, на которой ошибка сегодня маскируется HTTP 200. Отдельный тест таблицы переходов такой дефект не поймает. Для веб-пирамиды первым шагом заменить старые импорты и фикстуры, добавить тестовый `SECRET_KEY` до импорта и проверять публичные маршруты через OpenAPI и HTTP. Результаты старого smoke с переопределёнными зависимостями и устаревшими DTO не заменяют эту регрессию.
