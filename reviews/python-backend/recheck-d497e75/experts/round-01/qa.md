## Приоритетные результаты

### P1. Нельзя отключить клиента с заявкой в работе или на проверке

После обычного `POST /admin/tickets/`, назначения сотрудника того же отдела и `PATCH /admin/tickets/{id}/start-work` вызов `PATCH /admin/clients/{id}/disable` вернул **400**. Отдельное соединение показало, что клиент остался включён и заявка осталась `AT_WORK`. После успешного `finish-work` повторный вызов тоже вернул 400, клиент и сотрудники остались включены, заявка осталась `READY_FOR_REVIEW`.

`ClientApplicationService.disable` читает все открытые заявки клиента. `ClientService.disable` вызывает `suspend()` для каждой открытой заявки, хотя его собственное описание предписывает пропускать `AT_WORK`. Таблица переходов не допускает `SUSPENDED` ни из `AT_WORK`, ни из `READY_FOR_REVIEW`. Последнее прямо расходится с заметкой автора. Состояние `TicketUser.SUSPENDED` действительно финальное и разрешено из `WAITING_FOR_CONFIRMATION`. Воспроизводимый блок находится в переходах внутренней заявки. ### P1. Известные некорректные входы всё ещё превращаются в 500

Оба штатных `POST /admin/tickets/` и `POST /user/tickets/` с текстом из пробелов вернули `500 {"detail":"Internal server error"}`. `TextOfTicket` требует от 2 до 4000 символов после удаления крайних пробелов и выбрасывает `ValueError`. HTTP-модель администратора принимает любую строку, модель пользователя требует только один символ до удаления пробелов. Независимый сценарий `GET /admin/departments/-1` тоже вернул 500. DTO выбрасывает базовый `ApplicationValidateError`, тогда как таблица HTTP покрывает только его подкласс `TicketInputValidationError`. Точечная проверка ввода либо преобразование известных ошибок на границах сохранили бы различие между 4xx и серверным сбоем. ### P2. Ответ 400 может содержать полностью раскрытое представление заявки

В обоих запросах отключения поле `detail` содержало строковое представление всего `Ticket`, включая текст, описание, историю статусов и идентификаторы сотрудников. Ошибка перехода форматирует весь `self`, а стандартный обработчик для `DomainOperationError` возвращает `str(exc)`. Вызов сделал синтетический администратор с полным комплектом прав. Проверка подтверждает лишние данные в контракте ошибки и не утверждает доступ к чужим данным. Для 500 обобщённый ответ работает. ### P2. Тип срочности приведён к единому виду в HTTP, а значение по умолчанию в DDL осталось числом

Штатное создание с `urgency: "urgent"` сохраняет строку в `urgency_level`. HTTP отвергает число 2 с 422. В опубликованной схеме у той же колонки `INTEGER NOT NULL DEFAULT 0`, а mapper вызывает `TicketUrgency(raw)`, чей enum допускает только три строки. В синтетической заявке с уже записанной корректной историей заменил срочность на 0, после чего обычный `GET /admin/tickets/{id}` вернул 500. Любой список, который загружает такую строку, также прервётся на mapper по коду. Это сохраняется для импорта либо прямой вставки с умолчанием даже при решении автора пересоздавать учебные БД. Размер затронутых данных не определял. ### P2. Постоянного refresh-хранилища нет, сессии зависят от процесса

Два глобальных объекта в зависимостях фактически указывают на один singleton-контейнер в процессе. Для HTTP refresh и logout код проверяет `subject_type`, а отзыв по имени дополнительно ограничен субъектом из access-токена. Само общее хранилище не доказывает смешения доступов. При перезапуске записи refresh пропадают, экземпляры разных воркеров хранилищем не делятся. Единственный воркер в Docker согласуется с текущим режимом. `cleanup_expired_tokens` определён, связки с жизненным циклом приложения нет, поэтому невостребованные просроченные записи остаются до перезапуска. Хеш служит ключом словаря, объект в памяти по-прежнему содержит исходный токен. Постоянную реализацию и вызов очистки не нашёл. Эти выводы статические. ## Достоверность существующего набора тестов

Запускал из временного каталога Python 3.12.14, pytest 9.1.1, FastAPI 0.143.0 и Pydantic 2.14.1. Веб-набор без ключа останавливается при импорте `src.web.main`. С синтетическим ключом сборка останавливается на отсутствующем `src.web.models.mappers`. После исключения только этого файла **18 failed, 13 passed**. Провалы включают прежние сигнатуры токенов и сущностей, старые поля HTTP в smoke-фикстурах и обход `app.routes` через `APIRoute`. В установленных закреплённых версиях FastAPI вложенные маршрутизаторы представлены отдельными контейнерами. OpenAPI построил 83 пути, обычные HTTP-запросы дошли до действующих роутеров. Старый список контрактов сам по себе расходится с кодом, например ждёт `submit-for-review`, тогда как ветка выставляет `finish-work`. Integration/full/contract-фикстуры копируют `db/admins.db`. Их в этом раунде не запускал, проверил опубликованную схему напрямую и прошёл рабочие входы с синтетическими данными.
