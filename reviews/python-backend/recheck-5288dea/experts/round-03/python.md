### Границы patch03

Он не отзывает сессии при password/disable и не добавляет идемпотентность. Он также не восстанавливает уже утраченную дату первого login у сессий, ротированных старой версией: текущий payload хранит только дату последней ошибочной ротации. Для строгого перехода на первоначальные семь суток старые сессии следует завершить с новым login; бесшовное восстановление неизвестных дат невозможно. Production env overrides остаются отдельной конфигурацией; patch не объявляет их проверенными.

## Полный отзыв и ключи: отдельные законченные feature-изменения

**Полный атомарный отзыв не является безопасным независимым малым patch без изменения UoW/interface.** Сейчас auth-service завершает чтение аккаунта до выдачи сессии; TokenStorageSQLite открывает отдельную транзакцию; mutation services не имеют session repository. Post-commit revoke-hook оставляет неатомарность и окно устаревшего login/refresh. Необходимы общий session repository/UoW/основная БД, account_id+subject identity, общий lock/CAS-протокол auth выдачи/ротации и password/delete/disable/Client cascade, согласованная политика memory режима. Проверки: failure до COMMIT с rollback обеих частей, account replacement, restart/workers и конкурентные login/refresh против отзыва. Требование sid-check каждого access не добавляется.

**Идемпотентность тоже не исправляется маленьким локальным patch.** Полный объём — десять создающих API-маршрутов, scope ключа и fingerprint с target, repository/result table в той же UoW, подготовленный response до единственного COMMIT, 24 часа от успешной фиксации, rollback+новая UoW для unique conflict/replay. Нынешние внутренние commit helpers нужно согласовать с этой границей; post-response middleware или UNIQUE на Ticket.user_ticket_id не выполняют контракт. Отдельный Account исключён, встроенный покрывается родителем. Проверки — все маршруты и изоляция scopes, повтор/другое тело/новый ключ/без ключа, rollback, потеря ответа, конкурентный дубль, expiry. Неутверждённые лимиты и ожидание должны быть выбраны при реализации; серверные автоматические retry не вводятся.

Обе функции остаются открытыми обязательными задачами. Их контрактные красные тесты полезны и не должны превращаться в фиктивно зелёные заглушками. Patch03 закрывает только согласованный lifetime scope, отдельно и проверяемо.
