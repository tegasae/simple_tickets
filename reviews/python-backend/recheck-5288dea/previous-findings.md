## Прежние открытые темы

| Тема | Текущий статус |
|---|---|
| Self-assignment guard и PostgreSQL | **Остаётся как риск.** В self/remote ветвях нет touch. Runtime PostgreSQL не проверен; SQL API пока SQLite-only. Предлагаемый guard patch проверяется отдельно |
| Контакт0 и обязательный контакт | **Вопрос решён, правило реализовано:** сохранённый положительный контакт у пользовательского происхождения обязателен; очистка Admin0 отклоняется, User0 нормализуется в owner |
| Начальный TicketUser.CREATED.actor | **Остаётся.** Теперь прямо требуется фактический Admin при регистрации за User; источник factory по-прежнему owner |
| Внутренний automatic Ticket actor0 | **Не подтверждён дефект.** Документы явно определяют SYSTEM_GENERATED; новое правило CREATED не отменяет его однозначно. Вопрос scope сохранён |
| JSON comment | **Остаётся.** Старое наблюдение получило прямое требование строки, но VO всё ещё сериализуется объектом |
| Смена отдела Admin | **Больше не неоднозначность.** Владелец подтвердил запрет при текущем назначении; код его обеспечивает, старая документация о толькоAT_WORK устарела |
| Finish отключённого клиента | **Решено и работает:** READY_FOR_REVIEW, отдельная финализация Admin; это не ошибочно зависшая карточка |
| UNIQUE пары | **Больше не применимо как требование.** Допускается будущее1:N; текущий публичный сценарий создаёт одну пару. Требовать UNIQUE в исправлениях нельзя |
| Постоянный отзыв refresh и абсолютный срок | **Остаются невыполненными обязательствами.** Теперь явно подтверждены владельцем; старые access могут жить5мин, это не разрешение получать новые access через старый refresh |
| Повторы / Idempotency-Key | **Остаётся отсутствующей обязательной функцией.** Все создания кроме отдельного Account, ключoptional, хранение24ч; серверные авторетраи не запрошены |
